# QMF Test Strategy

The quality toolchain and quality tiers are ratified. QMF's own source is governed by ruff (format + lint), pyright strict workspace-wide, and pytest; coverage is measured per package on every change with an **80% floor**, and the modules implementing the CT-01 (money) and CT-02 (time) primitives require **100% branch coverage** (DEC-0101). Three quality tiers bind to factory events, not Git-host mechanics (DEC-0102). Every package ships executable tests **and reference usage demonstrating its public contract** (L27) as tier-1 artifacts (DEC-0101, DEC-0096). Public value types are frozen dataclasses; seams are `typing.Protocol`s (DEC-0101). The venue contracts CT-18 through CT-21 are ratified surface (DEC-0136, DEC-0137, DEC-0138), and the risk contracts CT-22..25 plus CT-27..32 are ratified surface as well, **defined-unwired**: their public shape is conformance-testable, owned by `qmf-risk` and run by consumers, while no runtime exists and composition-root mediation carries every edge (DEC-0143 through DEC-0155). A specification whose own contract schema is still GAP-open — the deferred look-ahead gate — is not yet test-complete; naming the GAP preserves the uncertainty but does not satisfy a gate (DEC-0004, DEC-0096).

## Quality tiers bound to factory events

| Tier | Command | Runs when | Adds |
|---|---|---|---|
| Tier 1 | `poe check` | Every factory work unit (worktree / temp branch) | fmt + lint + types + unit + coverage (DEC-0102) |
| Tier 2 | `poe check-integration` | Landing into the integration branch | integration tests + **contract tests**, each package in an **isolated per-package environment** so an undeclared import fails rather than resolving through the shared workspace venv (DEC-0102, DEC-0100) |
| Tier 3 | `poe check-release` | Ship / release from integration | build all packages + clean-install smoke on both tier-1 OSes (Windows 11 x86-64, Ubuntu LTS x86-64) (DEC-0102, DEC-0099) |

A **contract test** is an executable conformance test for a `CT-*` contract's public shape, owned by the contract's owning package and run by the producer and all consumer packages at tier 2 (DEC-0102). A package may declare a test-only dependency on a contract's owning package purely to run its contract tests; that is not a ratified runtime edge (DEC-0100). Commands are host-neutral and bind to GitHub Actions only when a remote exists; factory-internal review layers stack on top, never replaced (DEC-0102).

## Test levels

| Level | Scope | Proof | Exclusions |
|---|---|---|---|
| Static and documentation gates | Ledger, gaps, inventory, component graph, contracts, registry, docs | IDs resolve; dead/superseded decisions are not revived; dependency and layer rules hold (default-deny edges, DEC-0120); docs and code-facing contracts exist before implementation | No product behavior claim from prose alone (DEC-0004) |
| Unit (tier 1) | Pure values, validation, policy, transformations, indicator and structure behavior | Named behavior and failure-mode assertions through public interfaces; no network; injected clock (never the system clock); declared random seed | No external service, physical store, trading runtime, or broad mock estate (DEC-0007, DEC-0022) |
| Property / invariant (tier 1) | CT invariants, constitution laws, component `May never` boundaries | Generated valid and invalid inputs prove the invariant and prohibited side effects remain absent | No generated result may validate trading edge (DEC-0054) |
| Contract (tier 2) | CT-01 through CT-32 | Owner-defined conformance suite for the public shape, run by producer and consumers in isolated per-package environments; schema round-trip, declared boundaries, version compatibility, invalid-payload behavior (DEC-0102) | The deferred look-ahead gate is not filled from a recommendation; a risk contract is ratified surface and conformance-testable, but a defined-unwired contract has no integration or runtime proof (DEC-0143 through DEC-0155) |
| Integration (tier 2) | Selected store adapter, source adapter replay, backup/restore target, venue sandbox | Cross-component contract handoff, persistence, restart/replay, reconciliation, and failure propagation | No uncontrolled live trade; venue testing uses demo credentials only and factory sandboxes never hold live secrets (DEC-0136) |
| QMF acceptance scenario (tier 2) | A bounded chain of QMF components and contracts | Golden input, expected contract outputs/refusals, evidence lineage, deterministic replay | No trading-node application loop, backtesting library, MIS, QML, or product UI (DEC-0008, DEC-0009, DEC-0022) |

The runtime and packaging that run these tests are ratified: CPython 3.14 on the two tier-1 OSes (DEC-0099), a uv workspace of seven `src/`-layout packages (DEC-0100). Test and fixture paths inside each package are documentation-time layout detail, not an open foundation gap.

## Law and authority property tests

Ratified invariants and `May never` clauses map to `<contract-id>/invariant/<slug>` or `<component-id>/never/<slug>` and run at tier 1 (property) and tier 2 (cross-package). DEC-0096 and DEC-0101 make executable tests and reference usage tier-1 release artifacts.

## Causality, seal, and synthetic evidence

The causality fixture family includes a knowable case, an unavailable-at-cutoff case, a late correction, and deterministic replay carrying event-time, knowledge-time, and source identity. The bitemporal ingredients are ratified (DEC-0117); the pass/refusal gate itself is deferred with the backtesting sitting (`GAP(GAP-0016)`, DEC-0121).

The seal family builds a CT-12 release, exercises default research splits, and checks that no sealed identity appears; the 12-month seal is a `policy rejection` refusal at every read boundary (DEC-0119). It references `registry:raw_history_retention_policy` and `registry:historical_holdout_months`.

Fixture metadata distinguishes source evidence, controlled replay, and synthetic inputs. Synthetic inputs may exercise infrastructure and failure handling but may not be cited as proof of trading edge (DEC-0007, DEC-0054).

## Completion guidance

A specification is test-complete when its contract schema is ratified, its tier-1 unit and property tests pass with coverage at or above the 80% floor (100% branch on CT-01/CT-02 primitive modules), its tier-2 contract tests pass in isolated per-package environments, and it ships reference usage (DEC-0101, DEC-0102, DEC-0096). Traceability cites FEAT, COMP, FM, CT, DEC, and GAP IDs and never substitutes a coverage percentage for behavior evidence. A specification whose own contract is still GAP-open (the deferred look-ahead gate) is not test-complete or releasable; an explicit GAP records why the test cannot exist but does not count as a passing test (DEC-0004, DEC-0096). A risk specification is ratified surface and contract-conformance-testable, yet stays not-runtime-complete while defined-unwired: its tier-2 contract tests may pass, but no integration or acceptance proof exists until the node wires it (DEC-0143 through DEC-0155).

## The trading node's QA standard (TN-23)

The trading node (COMP-QMN, FEAT-0031) ships under the platform's permanent battery **plus** additions that make the money-path proofs and the risk golden scenarios earnable in CI rather than asserted once on live infrastructure (DEC-0208). The node adds no profit gate and invents no latency budget: the standard proves machinery, not performance (DEC-0208).

### The permanent battery and mutmut on the money path

The battery is Skylos (including its infrastructure-as-code scan of the systemd unit files), `vulture`, the four tier-1 scanners, the coverage floor, and the Linux CI lane pinned to `ubuntu-24.04`, alongside **requirements-first independent tests in the `qa/` tree** (DEC-0208, DEC-0201). Nightly **`mutmut` is extended to the node's money-path modules** — door-path wiring, command mint, equity derivation, drift decomposition, sizing-ladder evaluation, and virtual-ledger folds — at the ratified kill floor (DEC-0208). It runs **against the branch that carries code** — `integration` until the operator's squash-merge lands the node on `main`, then `main` — and a **"zero mutants classified" run fails closed and alarms** rather than passing vacuously, because a scheduled job left pointed at a branch with no node code would classify nothing and pass silently (DEC-0208, DEC-0201).

### The venue conformance double (FEAT-0023) and the replay-diff distinction

A **venue conformance double is a required node artifact (FEAT-0023) and is the third `VenueClientPort` implementation** — it implements the same port, or the suite proves nothing about the port (DEC-0208, DEC-0228). One conformance suite that **both the double and the live cTrader client must pass** carries UNKNOWN-outcome fixtures per trigger (`timeout | transport-error | disconnect`) and the superseded-by-fill cancel read-back (DEC-0208). This is what lets the money-path proofs and the QA-debt discharge be earned deterministically in CI. It is **separate from replay** (TN-21): replay diffs recorded observations through the same loop on the replay frontier clock and carries no fill simulation, moving only when a decision moves, while the conformance double drives synthetic fault fixtures (DEC-0208, DEC-0206).

### The four golden scenarios and FAILURES.md completeness

**The four risk golden scenarios — [SCN-0006](../../scenarios/SCN-0006-book-paper-transition.md), [SCN-0008](../../scenarios/SCN-0008-pair-scoped-news.md), [SCN-0010](../../scenarios/SCN-0010-risk-boundary-conflicts.md) and [SCN-0011](../../scenarios/SCN-0011-qualifying-loss-bench.md) — stay defined-unwired until this node wires them, and no integration or runtime proof of them exists until it does** (DEC-0208). `FAILURES.md` completeness is **CI-gated, not promised**: a check asserts an entry for every typed-failure-id the node can emit (cross-checked against the failure-id enum), every entry has all six NFR-11 fields populated, every `operator affordance` resolves to a named door capability or operations-toolkit recipe that exists, and the observability alert allow-list is **generated from the register's `notification tier` column**, so the register and the pushed alert set cannot diverge (DEC-0208).

### Benchmarks

The node ships its own benchmark harness at **test status**, measuring wall-clock **and** peak RSS across a four-point seat sweep (10, 40, 100 and 200 seats) against the design-load reference (`registry:design_bot_concurrency`) (DEC-0208). The harness **never runs concurrently with a slice-driving node process**: it runs before the doors open or from node stand-down, holds `governor_cpu_budget` and `governor_memory_budget` (soak-blocking, not merely live-blocking), and **every baseline and gate run records the node's lifecycle state at measurement** — a run recorded while the loop was driving slices is neither a baseline nor a gate, or the baseline is contaminated by the node and the node's slice latency is contaminated by the baseline (DEC-0208, DEC-0236). The first Linux baseline, recorded on the VPS tuple in the soak's first hours before the doors open on live bindings, becomes the regression gate and also satisfies the bind-time rung baseline and the light-claim gate. **Each benchmark's regression threshold is stated when its baseline is recorded, as a multiple of measured run-to-run variance** — a baseline without one is not a gate — and the operator's own latency figure is recorded as a **watched target, never a budget**. The gate is evaluated on the VPS and in the nightly window; CI runs the harness for correctness only (DEC-0208).
