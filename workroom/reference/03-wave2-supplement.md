## In plain words

1. Wave 1 settled *architecture*: one broker port, one kernel, one canonical result document. Wave 2 settled *physics* — the fill, the clock, the calendar and the settlement date — which is where a forex prop-firm attempt actually dies.
2. The strongest new idea is `hftbacktest`'s **two-clock replay**: every event carries an exchange timestamp and an arrival timestamp, and the same tape is replayed twice — once for the simulated venue in venue-time order, once for the strategy in arrival-time order. Wave 1 gave `Provenance` its two fields; wave 2 shows how to make them load-bearing, so look-ahead becomes unrepresentable rather than merely tested for.
3. Second strongest: **the fill model's free parameter is fitted against live results, not guessed once.** A project that actually trades converged on QMF's Novel Idea #4 and supplied the method — trade small, plot backtest against live equity on one axis, tune until they agree. That turns backtest fidelity from a constant into a measured, improving quantity.
4. The corollary is a rule wave 1 never stated: **touching a price is not filling at it.** Trading *through* a resting limit is a certain fill; trading *at* it is a probability. The retail default must be zero, and buys must fill at the ask and sells at the bid from stored two-sided quotes — never mid.
5. The calendar assignment produced a clean negative result that is worth as much as a positive one: the two most mature calendar libraries in Python model spot forex as **one flat session, Sunday 17:00 to Friday 17:00, no holidays**. There is no multi-session, DST-misaligned forex calendar anywhere in the ecosystem. `qmf.venue_model` is greenfield, and now that is measured rather than assumed.
6. `fx-value-date` — 270 lines, one author, days old — nevertheless contains the exact settlement arithmetic a swap/rollover ledger line needs: spot-lag table, the USD intermediate-day rule, modified-following, end-of-month forward rolls. It is a specification to re-derive and test, not a dependency, and it fills the gap wave 1 left open at ledger #36.
7. Six "epistemic sketch" repos independently reinvented QMF's safety rails. Three are honest, narrow, well-tested tools. Two wrap good code in self-citation networks and, in one case, a patent-pending notice bolted onto an MIT licence. One is not what its catalog listing said at all.
8. The single most transferable statistic in the wave: `honest-signals` measured that a naive Wald interval calls **14 findings where a cluster-robust interval calls 3** across the same 105 cells. Same-day pattern hits across different tickers are one market move observed twice, not independent draws. Wave 1's ledger #50 named the right idea; wave 2 supplies the arithmetic that makes it bite.
9. The wave-1 catalog's "days-old, single-author, possible self-promotion" flag turns out to have **low discriminating power**. It correctly caught `pit-release-gate`'s citation network and `autonomous-audit`'s mis-listing; it wrongly implied `riskkit`, `rulelint` and `backtester-mcp` were not worth reading. Unvetted means unverified, not junk — and a well-written README is exactly what a plausible self-promotion repo also has. The flag buys a careful read, not a verdict.
10. Net effect on the plan: **still nothing overturns the module map.** Two wave-1 ledger rows are materially wrong and are corrected below (#49's rulelint half, #9's scope). Four are sharpened. Everything else is addition: forty-three new rows, heaviest in Ring 5 and Ring 6, which were the two thinnest rings after wave 1.

## Corrections to wave 1

**W2-1 — Ledger #49's `rulelint` half is wrong. It is a dead-condition linter, not a look-ahead linter.**
Row #49 reads *"Look-ahead is caught mechanically by replay… `momoddo/rulelint` replays each rule condition bar-by-bar and flags anything computable only with future data"*, and calls it "two independent implementations of the same check." It is not. `rulelint` (`rulelint/core.py:122-241`) replays each condition and counts how often it was **true, false, or unevaluable**, rolling up to `ok`/`never_joint`/`dead`/`unknown`. It detects conditions that **never fire**. A genuine look-ahead bug typically makes a rule fire *too often* — and would be reported `ok`. The two checks share one worked example (an off-by-one shift producing both symptoms), which is presumably how the catalog conflated them. **Amend #49 to:** the look-ahead check is Freqtrade's withhold-the-future replay (`freqtrade/optimize/analysis/{lookahead,recursive}.py`) plus QMF's own registration-time causality property test (Novel Idea #1); `rulelint` contributes a *complementary, distinct* dead-branch check and — more valuably — the three-state verdict now recorded as #105. Its own documentation is the best part: it names the obvious wrong fix (a percentile-rank transform inherits the series' trend and empties the same tail it was meant to protect — measured at a 40.8-point gap on its own test data) rather than shipping it silently.

**W2-2 — Ledger #9 is correct but narrower than it reads.** *"A point-in-time query that would need the future is unexpressible"* covers read-time correctness only. `pit-release-gate`'s comparison table (`README.md:133-146`) draws the line QMF's design had not: an as-of join proves no value was read before it was available; purged/embargoed CV proves train and test do not overlap in time; **neither proves that the set of entities which had reported by t was not itself selected on the thing being measured.** For single-instrument forex this is often moot, but any cross-sectional or multi-pair confluence built on staggered-arrival facts is exposed. #9 stands as written; #78 is the second half it needs, and the two should be cited together.

**W2-3 — Ledger #35's fill-assumptions manifest is necessary but not sufficient; it needs a fitted parameter and a bid/ask rule.** #35 established that fill assumptions are named, versioned, seeded and cited. Wave 2 adds three things that change what goes *in* the manifest: (a) the parameter must be **fitted against live fills**, not declared once (#97) — a manifest of guesses is still a manifest of guesses; (b) equality between a limit price and a traded price is a **probability with default zero** (#95), which #35 never states; (c) fills must come from **two-sided quotes**, buys at the ask and sells at the bid (#98), which requires `qmf.data.lake` to store bid and ask as separate columns from the first ingest — a data-layer consequence that was not visible from wave 1. Treat #95–#98 as the required contents of #35's manifest rather than as optional extras.

**W2-4 — Wave-1 line 20 and ledger #63 overstate what "unvetted single-maintainer repo" tells you.** The catalog study concluded that awesome-quant's newest entries are *"largely unvetted single-maintainer MCP wrappers"* and flagged this wave's shortlist as possible self-promotion. Read directly, the flag has low discriminating power. It was **right** about `autonomous-audit` (mis-listed; the catalog described a subpackage and shortlisted a 500-file live-trading platform) and about `pit-release-gate` (a self-citing multi-repo ecosystem with figshare "papers" and a patent claim). It was **wrong** as a quality signal about `riskkit` (full type hints, `py.typed`, Hypothesis property tests asserting the anti-martingale invariant, a changelog documenting a real self-caught bug — an inverted stop returning `ok=True` with a plausible R:R — and its fix), `rulelint` (tests pinning bugs the author shipped to live strategies, documentation that names the wrong fix), and `backtester-mcp` (Apache-2.0, 11 test files, real combinatorial PBO, a documented benchmark table with stated hardware). The sound reading of "2 stars, 0 forks, six weeks old" is **unverified**, not bad — and a well-written README is exactly what a plausible self-promotion repo also has. Amend the posture to: the flag buys a careful read and an `evidence_state: hypothesis` registration, never a verdict in either direction.

**W2-5 — Wave-1 conclusion #1 ("no honest market-structure library anywhere") holds, and now has a second, sharper piece of evidence.** The two most mature calendar libraries in Python model spot forex as one flat session — Sunday 17:00 to Friday 17:00 `America/New_York`, `weekmask = "Sun Mon Tue Wed Thu Fri"`, **no holidays at all** (`pandas_market_calendars/calendars/forex.py`) — and `exchange_calendars`' only 24/5 offering is a single `(None, time(0))` pair fixed in UTC. Even the CME Globex FX **futures** calendar collapses to one open/close per day. Four overlapping named sessions, a rollover hour distinct from a close, a weekend gap, and DST transitions landing on different Sundays in different countries exist nowhere in the ecosystem. Ledger #25 (QuantLib's calendar/convention split) remains the right vocabulary, but `exchange_calendars` is the better and more complete reference for it, and #86–#89 supersede #25 as the implementation guide.

**W2-6 — Ledger #20's "no prop-firm rule engine exists" needs one qualifier, and #23 is untouched.** `riskkit` is the closest artifact found in either wave to a gate engine with typed denial reasons: ~18 named checks in four categories, composed into one `ValidationResult`, with property tests on the caps. What it is **not** is a prop-firm rule engine — no phase machine, no trailing-drawdown anchor, no ratchet-and-lock, no breach-action vocabulary, and critically no durable state (#81). So amend #20's framing to: a component-level pre-trade gate with typed denials exists in the wild and works; the six-axis prop-firm ruleset and `Program`/`Campaign` (#21–#23) remain without prior art anywhere.

**W2-7 — C4's sequencing argument gains a constraint.** C4 records a build-order disagreement (Jesse's candle-perturbation Monte Carlo first, DSR/PBO after). Wave 2 does not change the order but adds a rule that applies to both ends of it: bootstrap CI and DSR answer different questions and must not collapse into one gate (#107), and PBO is available for a *single* confluence via parameter perturbation (#108) without needing a competing-strategy pool — which makes the "cheap check first" position cheaper still, since perturbation PBO needs no closed-form derivation either.

## Dead ends

One line each, so nobody re-studies them.

- **`autonomous-audit` repo root (`Autonomous-Asset-Management-Agents/Dev-Enviroment`)** — the catalog listed "a minimal offline stdlib-only ledger reference"; the repo is a ~500-file live-trading platform (FastAPI, Electron, Alpaca order execution, OAuth, a 9-agent LLM voting board, payments) whose own `CLAUDE.md` instructs AI auditors not to flag its disabled-auth and stub-credential-storage code. Read `packages/autonomous-audit/` only (that part is genuinely good, #110); never open the root for any other purpose.
- **`Sextant` as a codebase** — a personal Streamlit daily-only backtester, README footer "Built with Claude Code", no `.git` history in the clone, no tests over the one interesting file, strategies persisted as generated `.py` source. Ideas #74, #75, #103 and the checklist at #79 are the entire yield; there is nothing else in it.
- **`pit-release-gate`'s evidentiary apparatus** — three self-published figshare "papers" by two authors who also co-author the companion repos (`pit-audit-registry`, `pit-hygiene`) that cite them, none independently verifiable from the clone, plus a patent-pending notice under an MIT badge. The `gate.py`/`controller.py` code is clean and gave us #78; the citation network and the companion repos are not worth cloning.
- **`patternfetch.com`** — the commercial API supplying every hit-rate and baseline `honest-signals` displays, trusted rather than recomputed by the client (`models.py:407-419`) and unverifiable from the clone. The `stats.py` layer is stdlib-only and stands alone; do not chase the data source.
- **`backtest-bias`'s marketing half** — a fixed-price ₹7,500 "Bias Check" service, a Substack, a Kaggle profile and a DOI'd paper "under review at SSRN" occupy the second half of the same README as the code. The code and the death-curve table are real (#112); the surrounding apparatus is a funnel, not validation.
- **`rulelint` as a look-ahead linter** — it is a dead-branch linter (see W2-1). Anyone re-reading it expecting the check the catalog promised will waste the trip; the three-state verdict (#105) and its "percentiles will not save you" section are what is actually there.
- **`pandas_market_calendars.ForexExchangeCalendar` / `exchange_calendars.AlwaysOpenCalendar` / `WeekdayCalendar` as forex models** — one flat session, no holidays, no sub-structure, fixed UTC in two of the three. They are correct and honestly scoped, and they contain nothing QMF's `qmf.venue_model` can build on. Do not go looking for a richer forex model in either package; there isn't one.
- **`hftbacktest`'s L3 / order-book machinery** — `models/queue.rs:332-1128`, `proc/l3_local.rs`, `proc/l3_nopartialfillexchange.rs`, `depth/fuse.rs` (1,361 lines merging depth streams by per-level timestamp), `depth/roivectormarketdepth.rs`, and the snapshot/clear protocol all reconstruct an order book. cTrader gives QMX no queue, no historical depth and no sized trade prints; a `QueuePos` for cTrader would model a fiction whose parameters cannot be identified from data — worse than a crude model, because it looks rigorous.
- **`hftbacktest`'s Python binding as any kind of pattern** — `py-hftbacktest/hftbacktest/binding.py` is 2,390 lines duplicating the entire Bot API four times (`:650-984`, `:1093-1424`, `:1612-1946`, `:2055-2386`) because numba cannot dispatch dynamically. It exists for a constraint QMX does not have.
- **`riskkit.RiskManager` as a Book/BMS template** — `manager.py:437-582` computes size and runs the gate in one call returning one object. Convenient for a single-actor bot, wrong for QMF, where the researcher must run the BMS gate alone as a hard disqualifier inside a fitness function without re-running Book's money math. The six underlying components read individually are the useful part; the façade is not.
- **`skfolio`'s investment-universe machinery** — `Portfolio`/`Population`/covariance/prior estimators have no concept of a broker, a spread, a stop, a lot or a prop-firm rule, which is the same gap wave 1 already found across the whole portfolio-optimisation space (#13, #17, #18). Only the estimator/CV/driver *shapes* (#84, #85, #111) transfer; do not re-read it for domain content.
- **`fx-value-date`'s T+1 pair table** — `USD/CAD`, `USD/TRY`, `USD/PHP`, `USD/RUB` and silent on other commonly-T+1 pairs such as `USD/MXN`. The four algorithms are worth porting (#90); this specific table must be re-derived from a primary source or the broker's observed behaviour, not copied.
- **`hftbacktest`'s "negative latency encodes rejection"** — `latency.rs:78-86` with `order.rs:147-152` overloads one signed integer with a mode flag. Compact, and a trap: a sign error becomes a silently wrong fill time rather than a crash. QMF's typed `outcome ∈ {ACCEPTED, REJECTED, DENIED_LOCALLY, UNKNOWN}` already beats it.
