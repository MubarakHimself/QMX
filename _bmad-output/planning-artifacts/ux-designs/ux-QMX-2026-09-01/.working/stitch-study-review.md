# QMX desktop study — review record

Status: exploratory; no layout, palette or control is approved by generating it.

Project: https://stitch.withgoogle.com/projects/2400353520556836326

## Question being tested
Can one durable outer navigation support substantial agent work, composed quantitative tools, and later review of the same run from another environment?

The three states are one illustrative scenario, not a mandatory product workflow. Direct Python work and independent use of other environments must remain possible. The environment roster, project/workspace relationship, and final tab semantics remain open.

## Review criteria
- Outer navigation remains identifiable while environment interiors change.
- Agent conversation has useful working space; code and tables are legible.
- Context is visible: selected project, inputs, source versions, linked instruments.
- Linking changes only intended panels and preserves comparison context.
- A background run remains findable independently of the conversation.
- Review shows outputs, provenance, failures/attention and return to source work.
- No unrequested final token system, mobile design, forced graph editor or automatic trade deployment is adopted.

## Questions for later reconciliation with Grok
These are UI expectations to discuss, not findings of backend defects:
- Which identities persist for sessions, runs, inputs, artifacts and versions?
- What happens to a running task when its tab closes or the client reconnects?
- Can a user inspect the precise context an agent can act on, including later changes?
- How do linked selections, pinned comparison inputs and multiple views interact?
- Which run controls are supported (pause, cancel, resume, retry), and what do they actually guarantee?
- How are concurrent human/agent edits and versioned outputs reconciled?
- How can additional tools/views participate in navigation and saved arrangements?

## First-pass findings
The three generated screens preserve a common outer rail and environment tabs while giving Research a different interior. The agent can occupy a full workspace or accompany tools. Run R-024 and session SES-8821 provide visible cross-environment continuity. These are useful proposals, not verified interactions.

The initial workbench uses undersized text and crowded headers, has unused height below its panes, and marks linked selection as a filter. Some generated example content conflicts with task state: queued rows already contain results; the completed-review footer still names R-024 as active. It invents infrastructure, model names, confidence figures and stronger investment conclusions than requested. Do not treat any generated numbers or architecture labels as requirements.

A single focused refinement of screen 02 was requested to address text scale, pane height, header hierarchy, link semantics and pending results. Screens 01 and 03 remain initial studies; their data semantics need correction before an interactive prototype. Stitch also created an automatic style board despite the prompt; it is not an adopted design system.

## Preservation and interaction limits
The initial three screens were exported through Stitch's ZIP export with HTML source and PNGs to stitch-initial-export/. A separate tool-produced DESIGN.md resides only inside that raw export; it does not replace QMX's unfinalized design documents. The local stitch-study.html viewer switches the static screenshots. Automated browser verification of the local file was blocked by browser URL policy; no bypass attempted. The native exported PNGs were visually inspected.

The initial preview's Background action was clicked and produced no visible state change. Do not describe the study as a functioning run-management prototype.

Reference attachment later succeeded through clipboard image paste (public Refero Manus and Runey screenshots), after both plus-menu file chooser attempts timed out. They are attached in the composer for further reference use; neither the initial generation nor the already-running refinement received them.

## Refined workbench outcome
Stitch completed 02 Work alongside — refined. Export saved in stitch-refined-export/ with code.html and screen.png; the original is preserved. A second automatic DESIGN.md is raw producer output only.

Improved: simpler top-level navigation and environment toolbar; larger conversation text; multiline composer at pane bottom; more useful code/results area; no fake results in queued SPY rows; preliminary wording; explicit linked selection on chart/results rather than a filter; shorter status footer.

Still unresolved: vertically distorted chart axis labels, truncated context and chart title, dense table header, unverified independent scrolling/resizing/maximizing, and some remaining invented engine labels. The agent panel is substantial, but the chart's narrow column may be a poor default on a laptop. Do not approve it solely because it looks more polished. The image export is taller than the requested 1600x1000, so laptop-fit is not established.

Recommendation: use this study to discuss the shared outer navigation and agent/tool relationship. Then prototype three real actions: open/maximize a tool; move between environments while preserving task context; reopen a completed run and its conversation. Do not continue broad image generation before that structural review.

Trial usage: one initial three-screen generation plus one focused screen refinement. No UX Pilot generation, paid upgrade, backend implementation, final spines or deployment.
