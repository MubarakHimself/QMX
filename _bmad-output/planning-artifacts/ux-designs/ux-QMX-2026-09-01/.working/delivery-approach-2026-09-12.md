# QMX delivery approach — discussion proposal

Not an implementation authorization, finalized spec, schedule commitment or substitute for the existing QMX architecture.

## Correct the product model before generating build instructions

The Sol transcript audit identifies the missed distinction: the global entry mechanism opens durable department/domain worlds, not just object tabs in one universal interface. Resolve the opened-world hierarchy and transitions before freezing shell specifications. Preserve department-local freedom, shared STRATS identity and the integrated Trading Node area. See `layout-intent-audit-2026-09-12.md`.

## Spec features with BMAD in bounded packages

Use `bmad-ux` for behavior/visual decisions; `bmad-spec` for each selected coherent capability package; `bmad-architecture` to ratify reuse and specify missing boundaries against existing spines; then `bmad-create-epics-and-stories` for independently testable work and Grok's `bmad-build` for implementation. Do not rebuild the project-wide architecture or run every available skill. Do not maintain competing story lists in both spec breakdown and epics; choose one dispatch record when the first package is ready.

Each Grok package needs:

- User outcome and explicit exclusions.
- Approved relevant screen/state references, not rejected exploration sketches.
- Inputs, actions, outputs and durable identity/version rules.
- Implemented-with-evidence versus documented/unwired versus new requirements.
- API/query/event contracts, failures, permissions and concurrency behavior where applicable.
- Observable acceptance examples and verification commands.
- Exact dependencies and a small review boundary.

Suggested package families, not a committed roster: world navigation/state restoration; STRATS browsing and bot profiles; template-based experiment setup; run/progress/results; comparison/what-if; data quality; portfolio/sizing simulations; contextual agent integration. A family can produce several slices. Do not mechanically create 17 specs from the research table.
