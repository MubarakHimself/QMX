## New facts

Everything below is new relative to the seven prior findings and bears directly on venue-adapter design.

**Numeric scales — three distinct and independent systems. Grade: strong (primary-proto + primary-doc).**

1. **Wire price scale, market data = 1/100000 integers.** *"Bid price. Specified in 1/100000 of unit of a price. (e.g. 123000 in protocol means 1.23, 53423782 means 534.23782)"* — this comment exists on exactly `ProtoOASpotEvent.bid/ask/sessionClose` and `ProtoOAOrder.relativeStopLoss/relativeTakeProfit`. **Provenance correction:** `ProtoOATickData.tick` (*"// Tick price."*) and `ProtoOATrendbar.low` (*"// Low price of the bar."*) carry **no** 100000 comment in the proto — the divisor for ticks and trendbars is attested **only by the docs page** and its sample code (`GetPriceFromRelative(symbol, relative) => Math.Round(relative / 100000.0, symbol.Digits)`). Docs-attested, not proto-attested, for that half. `https://help.ctrader.com/open-api/symbol-data`
2. **Order/position/deal prices are protobuf `double`s carrying the actual price**, not scaled integers: `optional double price = 5;` (position VWAP), `stopLoss`, `takeProfit`, `ProtoOADeal.executionPrice`, all conversion-rate fields. **An adapter that applies /100000 uniformly will corrupt the execution path.** Grade: strong (primary-proto).
3. **Money scale = per-message `moneyDigits` exponent**: *"Specifies the exponent of the monetary values. E.g. moneyDigits = 8 must be interpret as business value multiplied by 10^8, then real balance would be 10053099944 / 10^8 = 100.53099944."* Each occurrence names exactly which of its own fields it scales. **Carrier list corrected and extended to nine messages** — the prior six (`ProtoOATrader`, `ProtoOAPosition`, `ProtoOADeal`, `ProtoOAClosePositionDetail`, `ProtoOADepositWithdraw`, `ProtoOABonusDepositWithdraw`) plus three in `OpenApiMessages.proto` that were missed: `ProtoOAExpectedMarginRes` (field 4, *"Affects margin.buyMargin, margin.sellMargin"*), `ProtoOAMarginChangedEvent` (field 5, *"Affects usedMargin"*), `ProtoOAGetPositionUnrealizedPnLRes` (field 4, *"Affects positionUnrealizedPnL.grossUnrealizedPnL, positionUnrealizedPnL.netUnrealizedPnL"*). **An implementer following the short list fails to descale margin and unrealized PnL.** Note `ProtoOAGetPositionUnrealizedPnLRes.moneyDigits` is **`required`**, unlike every other (optional) occurrence. Grade: strong (primary-proto).
4. **Volumes are in cents (0.01 units) everywhere**: `required int64 volume = 2; // Volume in cents (e.g. 1000 in protocol means 10.00 units).`; `minVolume`/`maxVolume`/`stepVolume` *"in cents"*; `lotSize` *"(in cents)"*; `ProtoOAExpectedMarginReq.volume` *"represented in 0.01 of a unit"*. Depth-of-market size likewise: *"transform the depth quote size into units by dividing it by 100."* Grade: strong.
5. **Display precision is a third, separate axis**: `required int32 digits = 2; // Number of price digits to be displayed.` and `required int32 pipPosition = 3; // Pip position on digits.` — and `ProtoOAAsset.digits` (*"Precision of the asset."*) is yet another, distinct from symbol price digits. **`ProtoOALightSymbol` carries none of this** (only symbolId, symbolName, enabled, base/quote assetId, categoryId, description, sortingNumber) — full scaling metadata requires the heavy `ProtoOASymbol` via `ProtoOASymbolByIdReq`. A symbol-list-only bootstrap cannot decode prices. Grade: strong.

**Cross-currency / money-path fields. Grade: strong (primary-proto).**

6. `ProtoOATrader.depositAssetId` (*"Deposit currency of the account"*) is the account's booking currency. `ProtoOASymbol.pnlConversionFeeRate` = *"Percentage (1 = 0.01%) of the realized Gross Profit, which will be paid by the Trader for any trade if the Quote Asset of the traded Symbol is not matched with the Deposit Asset."* The **realized** counterpart, missed in the prior pass: `ProtoOAClosePositionDetail.pnlConversionFee = 10` — *"Fee for conversion applied to the Deal in account's ccy when trader symbol's quote asset id <> ProtoOATrader.depositAssetId"* — and that message's `moneyDigits` explicitly names it among scaled fields (*"Affects grossProfit, swap, commission, balance, pnlConversionFee"*). Direct evidence of where the API **does** convert: `ProtoOAPositionUnrealizedPnL.grossUnrealizedPnL`/`netUnrealizedPnL` are *"denoted in the account deposit currency"*, and `ProtoOAPosition.usedMargin` is *"in deposit currency"*. Bears directly on any foreign-money-stored-verbatim rule.

**Schedules and calendars — a second, non-UTC timezone axis. Grade: strong (primary-proto).**

7. `repeated ProtoOAInterval schedule = 13; // Symbol trading interval, specified in seconds starting from SUNDAY 00:00 in specified time zone.` with `optional string scheduleTimeZone = 26;`. Intervals: `startSecond` inclusive, `endSecond` **exclusive**, both from Sunday 00:00.
8. **`ProtoOAHoliday` carries its OWN `required string scheduleTimeZone = 4; // Timezone used for holiday.`** — missed in the prior pass, which named only symbol sessions as the non-UTC case. So `holidayDate` (*"Amount of days from 1st Jan 1970, multiply it by 86400000 to get Unix time in milliseconds"*), `isRecurring`, and its `startSecond`/`endSecond` are **all** measured in a broker-specified zone, not UTC. There are **two** independent non-UTC zone axes, both broker-supplied per-entity.
9. **No primary source links `scheduleTimeZone` to D1/W1 bar aggregation.** The relationship between trading sessions and bar boundaries is undocumented, leaving per-symbol/per-broker bar-boundary variation formally unresolved — which is precisely why finding 2 must not be hard-coded.

**Swaps and fees. Grade: strong (primary-proto).**

10. `swapLong`/`swapShort` are **doubles** with `swapCalculationType` (enum `{PIPS=0; PERCENTAGE=1; POINTS=2;}` — note the field comment names only PIPS and PERCENTAGE; POINTS comes from the enum), `swapPeriod` (hours), `swapTime` (*"Time in minutes from 00:00 (UTC)"*), `skipSWAPPeriods`, `chargeSwapAtWeekends`. Swap-free path: `ProtoOATrader.swapFree` (*"If TRUE then account is Shariah compliant"*) switches to `rolloverCommission` — *"charged daily as USD per current open volume of Position in lots. The Account charged in the Deposit currency"* — with `skipRolloverDays` and `rolloverCommission3Days` (*"Day of the week (in UTC) when Administrative Fee charge amount will be tripled"*). Two of the few explicitly-UTC anchors in the schema.

**Connection mechanics. Grade: mixed — flagging a contradiction.**

11. **The heartbeat interval is stated inconsistently across primary sources.** The proto comment says a client may send heartbeats *"when he needs to keep the connection open for a period without other messages longer than 30 seconds"*, while the FAQ says *"make sure that you send a heartbeat to the server at least once every 10 seconds"*. Grade: both primary-doc/primary-proto, mutually inconsistent. An adapter should use the **10-second** figure as the safe bound. `https://help.ctrader.com/open-api/faq/`
12. **Trendbars are not manufactured during quiet periods**: *"No, trend bars are only created if there are incoming ticks."* — bar series are gappy by design, not dense. Grade: strong (primary-doc). `https://help.ctrader.com/open-api/faq/`
13. `ProtoOASpotEvent.timestamp` is **opt-in only**, via `subscribeToSpotTimestamp = TRUE`. A default spots subscription yields bid/ask with **no server time at all**. Grade: strong (primary-proto).
