# Trading Node recovery scout

This is a temporary, documentation-only comparison package for restarting the deterministic Trading Node. It does not initialize Git, change code, recover the agentic system, or redesign the Backtest Engine.

## Result in one paragraph

The public GitBook already contains the durable core: bots propose; Books own admission, sizing, and the seven doors; BMS accounts for and constrains; KSA protects; Adapter executes mechanically; the operator holds final authority. It also contains Treasury cycle accounting, MIS as information rather than authority, Records evidence, registries/formulas, and the principal scenarios. The later local material makes that core substantially more precise: it fixes the three-node topology, persistence and evidence placement, CT-SYNC behavior, the `ADMITTED` and fail-mechanism-only paper lifecycle, unified registration, cTrader session ownership, CT-BOOK-03 schema discipline, exact arithmetic, news ownership, monitoring, and Console/Powers separation. It still does not describe a complete wired trading system. Some even-later BMAD stories add useful proof-level detail, but they also contain choices that were never folded back into the wiki and at least one direct conflict. Those choices are separated for re-ratification instead of being silently called current architecture.

## Recovery labels

| Label | Meaning for the restart |
| --- | --- |
| `BASELINE` | Already present in GitBook. Retain it, but do not present it as newly recovered. |
| `KEEP` | A later local clarification or ruling with sufficient authority to carry into the fresh Trading Node documentation. |
| `RECONFIRM` | Useful later BMAD/proof detail that should be explicitly ratified again before it becomes a fresh-project default. |
| `REOPEN` | Contradictory, incomplete, schema-pending, or provenance-uncertain. Leave visible and decide deliberately. |
| `DROP` | Superseded, attic-only, agentic/Backtest material, or otherwise outside this recovery. |

## Authority used for this comparison

Within the requested Trading Node scope, the comparison applies the local source rule: the active architecture spine/operator-ratified wiki governs architecture and mechanics; completed BMAD stories can supply later evidence but do not override the wiki silently; GitBook/recovered sources supply the baseline where the later layers do not conflict. A story being marked `done` proves that story's acceptance criteria, not that the surrounding component or epic was completed.

This is deliberately not a Wayfinder map or issue tracker. The user requested a disposable scouting artifact that can be handed to a fresh session and then removed.
