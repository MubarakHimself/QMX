# SCN-0012: An Agent Runs a Replay Backtest Against a Book

This scenario pins the golden QMB replay run end to end: an agent working as a quant runs one CLI command, the thin door resolves Book and BMS fragments by fingerprint through the single registry-read port, the config compiler produces one resolved run-config whose fingerprint becomes the run-id root, a `world = replay` binding is minted, the orchestrator spawns one governed isolated process, the run loop advances a frontier clock through event slices in the pinned sub-phase order with warm-up trading-locked and all fills optimistic-tainted, trading events land as journal events while the per-run log stays operational, the pure `run()` returns a CT-32 artifact and the orchestrator writes exactly one `role = confirmation` ledger line, and a later Book-bar read derives the per-requirement verdict that re-verdicts with no re-run when a blank requirement is ruled. Two failure branches — a stale Book ref and a synthetic store read — are pinned alongside. QMB is a **library** and a **CLI**, never an engine or a kernel; QMF is the only framework. Execution status: **ratified design (spine B-1..B-15 FINAL, ratified by operator delegation 2026-08-20); implementation is authorized only through the factory pipeline, never from these docs alone.** [DEC-0159] [DEC-0169]

## Given

The machine holds a current registry **as-of set** — an immutable, fingerprinted set of records and fragments at a `registry_as_of` instant — delivered by the passive file-sync hub (dumb storage, never the dead DEC-0084 central service). "snapshot" is banned vocabulary for registry state. Exactly ONE library-owned registry-read port serves every consumer: the config compiler resolves through it and the CLI door enumerates through it for autocomplete, so resolution and autocomplete can never answer differently — there is no door-side cache. [DEC-0165]

The target Book exists as a record resolvable through that port under a human alias, carrying its bench/sizing/exit-door policy; the paired BMS carries accounting, constraints, kill-line, and reporting. The bot is a registered plain-Python bot (QML is deferred, GAP-0047, and QMB tests plain-Python bots meanwhile) declaring typed parameters. The workspace has the `qmb` CLI provisioned as a pinned lockfile dependency — one CLI for agents and operator alike, its door built on the `registry:qmb_cli_pin` pin with the default sampler adapter on the `registry:qmb_sampler_pin` pin — both non-configurable exact version pins held by the registry. [DEC-0159] [DEC-0168]

QMB is an application composition root built ON QMF — never a QMF roster package. This run is the first sanctioned place the defined-unwired risk contracts (CT-22/CT-23/CT-27/CT-32 and kin) are legally wired, and they are wired in `world = replay` only; a replay binding can never gate live money. [DEC-0169] [DEC-0162]

## When

The agent runs, from the pinned CLI:

```
qmb backtest <bot> --book <alias>
```

`<alias>` is a human alias accepted at the door as UX; the resolved artifact will cite the Book, BMS, and bot definitions by first-class fingerprint (fp1), never `name@version`. The CLI door carries only adaptation logic — argument parsing, transport, refusal rendering, and autocomplete enumeration through the registry-read port; every capability it exposes exists once, in the library, as a pure function. [DEC-0159] [DEC-0160]

## Then

**(1) The door resolves the Book and BMS fragments by fp1 through the registry-read port.** Against the machine's current as-of set, the alias resolves to a Book definition and its BMS, and their generated **config fragments** are located by fingerprint. Each fragment is a schema-validated, fingerprinted DERIVED artifact carrying an AD-16 lineage edge back to its source — the Book charter (CT-22) and the BMS definition (CT-27) — never a newly minted registry kind and never free-hand-edited. Resolution runs in the library through the one registry-read port; the door adds no cache of its own. [DEC-0160] [DEC-0165]

**(2) The compiler produces ONE resolved run-config.** The layers compose with fixed precedence — invocation flags > run spec (the bot layer) > BMS fragment > Book fragment > workspace defaults. Book and BMS occupy DISJOINT key namespaces (Book: admission, sizing, exit-door policy; BMS: accounting, constraints, kill-line, reporting); a key collision is a **compile-time typed refusal**, and in any sanctioned overlap BMS outranks Book ("BMS accounts for and constrains Books"). `starting_capital` is a mandatory run-spec field seeding the binding's virtual ledger; here it is supplied and not overridden, so the run's fold stays rated — a flag override would stamp `seed_overridden` and force the fold to unrated. The resolved artifact stamps its own AD-5 integer format version and declares its AD-10 identity-vs-display field classification, so every door computes the **same fingerprint**; that fingerprint is the **run-id root and the ledger key**. The tunnel is never swapped — only its variables change. [DEC-0160]

**(3) A `world = replay` AD-29 binding is minted.** Exactly one binding per run, a DIFFERENT identity from any live binding of the same Book instance and incomparable to it. This is the sanctioned wiring point for the risk contracts, and the world is `replay`. [DEC-0160] [DEC-0169]

**(4) The orchestrator spawns one isolated process under the governor.** `run()` is pure and spawns no work (AD-15); the single impure orchestrator (the composition root) owns the OS-process spawn, an isolated output directory, and the injected log and ledger sinks. The governor bounds parallelism by `min(registry:qmb_governor_cpu_budget, registry:qmb_governor_memory_budget)` with a typed refusal or enqueue-on-full — never silent oversubscription — and the process carries the declared `registry:qmb_run_time_limit` and `registry:qmb_run_memory_limit`, whose breach is a typed `aborted` ledger line rather than a silent kill. No Ray, no required Docker, no daemon; sandbox and laptop run the same uv-installed package. [DEC-0161]

**(5) The run loop advances the frontier clock through event slices in the pinned sub-phase order.** The frontier clock IS qmf-core's AD-8 Clock protocol — monotonically non-decreasing, pulled to the minimum next-emit instant across streams, emitting wall/replay Instants — and it never chooses `world`. The identity-bearing per-slice sub-phase order is: (1) frontier advance + stream update, with higher-`BarSpec` bars derived from the finest declared base stream and emitted ONLY on completed boundaries — **a forming bar is never visible or actionable**; (2) scheduled position-level events (financing as a calendar-scheduled cash event, not an order fill); (3) resting-order execution through the fill/slippage/cost ports against the declared intra-slice path; (4) indicators/structure updated on closed data only; (5) strategy callbacks mint intents; (6) new intents rest for a later slice and never fill against the current slice's path. In-loop **warm-up** runs the same loop with the same adapters and trading locked — acting is a typed `policy rejection` — its length the AD-21 split-manifest embargo (never a second window), and the evidence range on the label is the trading interval, not warm-up. Inbound execution is a CT-23 Book-resolved intent (or a typed refusal); the ports execute an *authorized* intent, never a bot-sized order. Pre-GAP-0048, **all fills carry an `optimistic` taint**; a run's fidelity is the LOWEST fidelity of any adapter it bound, so such a run spends no split budget and claims no edge. Simulated-Instant typing is refused until GAP-0048. [DEC-0169] [DEC-0164]

**(6) Trading events emit as CT-13 journal events on writer-scoped replay streams.** Decision, order, fill, risk-transition and kin ride the ratified journal in the run's world — the trade record IS the CT-29 stream of this run's replay binding, not an invented format. The per-run log is an AD-14 **operational log only and is NEVER evidence**: under CT-11 only the raw archive and the journal bear evidence, and artifacts cite them. [DEC-0163]

**(7) `run()` returns the CT-32 artifact; the orchestrator appends exactly ONE ledger line.** The pure `run()` returns the canonical result plus a self-assessment and writes nothing. That result artifact IS a CT-32 performance-result in full — suppression and veto accounting included (so the run's own control-window and admission doors never masquerade as alpha decay), closed AD-40 unit-kind vocabulary — with chart series and trade-event references as DECLARED extensions (any downsample is a display-only derivative, AD-10-excluded from identity; trade-event references cite the CT-13 streams). The orchestrator appends exactly ONE WriterId-scoped JSONL ledger line with `role = confirmation`, carrying the AD-12 result label (evidence class; `provenance = sandbox` on factory-sandbox runs), the CT-32 fingerprint, the run's raw AD-40 unit-kinded measures, and the fingerprint of the Book bar **as resolved at run time**. Re-running the run id under its resolved config must reproduce the CT-32 fingerprint; a mismatch is a typed refusal. All human-facing rendering is a pure downstream function of the artifact — agents read the artifact, never the renderings. [DEC-0161] [DEC-0163]

**(8) Later, the Book-bar read derives the per-requirement verdict — and it re-verdicts with no re-run.** The ledger stored raw measures and the Book-bar fingerprint, never a pass/fail. One authoritative READ-TIME fold produces PER-REQUIREMENT outcomes against the cited AD-32 bar (structural parity on producer contract versions, unit-kind, and comparison rule); composite scores are banned; the verdict is legal only on `role = confirmation` lines whose adapters are the Book-declared set. While a requirement is blank the fold answers **not-yet-ruled**. When the operator rules that blank requirement next month, the accrued confirmation evidence **re-verdicts against the newly-ruled bar with NO re-run** — the bar changed, not the run. Standing caveat: a **replay-world verdict can never gate live money** — replay evidence feeds a live bar only where that bar's evidence requirements declare it, and this run's pre-GAP-0048 `optimistic` taint claims no edge regardless. QMB **publishes**; it never benches, promotes, or binds — that authority stays with the Book door and the operator. [DEC-0162] [DEC-0164]

## Failure branches

**Branch A — a second run binds a stale Book ref.** A later invocation resolves a Book ref that a fresher as-of set now shows superseded. The registry-read port raises an **AD-11 stale-evidence refusal** at severity `registry:qmb_stale_evidence_severity` (configurable UI-editable, no spine value). The as-of set itself is never configurable — a sweep freezes ONE as-of at batch admission for every trial, and after admission fragments resolve by explicit fingerprint, never `name@latest`. The fix is to re-resolve against the current as-of set, never to mutate the ref. [DEC-0165] [DEC-0157]

**Branch B — a run reads a store-persisted synthetic series (`generate`).** A run whose stream set reads store-persisted fabricated data is caught by provenance-derived world: world is derived, never caller-declared, so store-persisted fabrication is store-tainted and the run is typed `world = simulated`. For governed evidence that is a **policy rejection** until GAP-0048 — such a run is legal for infrastructure stress and strategy-logic smoke tests only. This contrasts with procedure-ephemeral perturbation (trade-shuffle, real-seeded block bootstrap that persists no synthetic series), which keeps `world = replay` with the procedure identity + seed in the label and a robustness-only claim class. L20 stands: nothing synthetic validates edge. [DEC-0164]

## Worked numbers

This scenario pins a control-and-identity flow, not an arithmetic computation, so there is no fixture number to freeze — and none may be invented. The load-bearing chain is an **identity chain**, not a calculation:

- resolved-config **fingerprint = run-id root = ledger key** — one fingerprint, computed identically at every door (DEC-0160);
- the single ledger line carries `role = confirmation` and cites the Book-bar fingerprint **as resolved at run time**, storing raw AD-40 measures and no pass/fail (DEC-0161);
- the verdict is a later per-requirement read-time fold, so the pass/fail exists only at read time and re-verdicts when the bar is ruled — nothing to store, nothing to recompute in the run (DEC-0162).

The only registry-referenced values in the walk are the governor and limit configurables (`registry:qmb_governor_cpu_budget`, `registry:qmb_governor_memory_budget`, `registry:qmb_run_time_limit`, `registry:qmb_run_memory_limit`), the staleness severity (`registry:qmb_stale_evidence_severity`), and the stack pins (`registry:qmb_cli_pin`, `registry:qmb_sampler_pin` — non-configurable exact pins, unlike the UI-editable rows before them). All are REFERENCED, never restated; the flow names keys, not literals, so a change to any of them leaves this walk intact. The `optimistic` taint on every fill, and the `not-yet-ruled` verdict on a blank requirement, are the honest defaults this run reports — not numbers, but the absence of any edge claim until GAP-0048 rules the fidelity content. [DEC-0164] [DEC-0169]
