## Why the prior sketches failed

The first three sketches preserved the broad idea of global entry, durable world tabs and local tools, but they still behaved like a human-only dashboard shell. They moved the same pieces around instead of changing the working grammar.

The specific error was treating agents as either:

- a separate top-level world;
- a button named "Agent sessions";
- or a future contextual side panel.

That misses the operator's correction: agents must be able to operate under each world, inside the selected context, with their own session/run/tool state visible enough to steer or audit. "Human-usable first" does not mean "no agent-aware layout." It means the human can do the work directly, while the same surface also exposes enough context, tools and state for agents to participate without becoming a generic chat overlay.

## What the three screenshots actually contribute

### Hermes Agent reference

Use as the model for an agent-native work surface:

- local agent/session navigation;
- persistent session identity;
- session tabs at the top of the work area;
- central conversation/work canvas;
- bottom prompt dock;
- capability, artifact and scheduled-job entry points;
- independent supporting panes such as browser/files/review when needed.

Do not use Hermes as the entire QMX shell, and do not force every department to look like a chat app.

### Global rail dashboard reference

Use only as the global entry discipline:

- thin persistent launcher;
- compact icons;
- global areas opened from one stable edge.

Do not copy the generic finance dashboard, big card structure or content layout.

### Fincept Terminal reference

Use as the model for dense financial workspace composition:

- global destination row;
- distinct open-work tab row;
- dense widget/canvas area;
- workspace controls for compacting, refreshing, adding and saving;
- status/readiness bars that belong to live data and operating context;
- multiple panels coexisting without one panel pretending to be the whole product.

Do not copy the terminal aesthetic as the design system yet.

## Revised layout grammar

The platform should be a three-level compositor:

1. Global launcher
   The thin rail or compact top entry opens major areas. It is not the product's content layer.

2. Durable world tabs
   Tabs represent opened environments, such as Research Lab, Library, Trading Node, Agent Hub or a named undertaking. A tab opens a whole world and restores its internal arrangement.

3. World-owned workbench
   Each world owns its local navigation, work tabs, tools, panels and agent lanes. The common shell provides identity, persistence and switching; the world supplies the layout that fits the work.

The important addition is that each world has an agent lane system, not a universal assistant dock.

## Strong revised composition

Recommended next sketch: **Agent-Native World Workbench**.

Spatial structure:

- Far left: thin global rail for Home, Worlds, Library, Trading Node, Agents, Settings and status.
- Top row: open durable worlds, with a plus action and optional split/pair control.
- Under the active world tab: world header showing selected world, current undertaking/object, data/execution state and permission posture.
- Left inside the world: local navigator for that world only. In Research this might be Inquiries, Materials, Methods, Experiments, Evidence. In Trading Node it might be Books, BMS, Positions, Events, Bindings. In Library it might be Strategies, Templates, Sources, Versions, Evidence.
- Center: primary human workbench. This is where the table, chart, notebook, code editor, candidate grid, result comparison or live telemetry sits.
- Right or bottom, depending on world and screen width: **agent lane**, not generic chat. It has local sessions, active tasks, tool stream, context chips, cost/usage, Plan/Act or safer equivalents if adopted, and visible target binding.
- Bottom or secondary strip: run/event/status ledger scoped to the selected work, not a single global green light.

The agent lane can appear in three modes:

- Collapsed: shows active agent/run badges and warnings only.
- Co-present: shares the workbench with the human, like Hermes/RoboQuant authoring, where the agent has context and tool stream visible.
- Expanded: becomes a full Hermes-style agent workspace while preserving the exact selected world/object/version as context.

The key rule: invoking an agent never loses the current workbench. It either runs beside it, under it, or opens as a paired/expanded agent world with a visible context link back.

## How this changes the earlier alternatives

Department Rooms is demoted. Its overview-first structure may still be useful for Home or a new world landing state, but it is too passive as the primary grammar.

Persistent Workbenches is partly kept. Its "resume actual work" instinct is right, but it needs agent lanes inside every world and more Fincept-like workspace controls.

Paired Worlds is partly kept. Pairing is useful for Library plus Trading Node, or Research plus Agent Hub, but pairing is an advanced composition mode, not the main answer.

## Explicit requirements from the operator

- A tab opens a whole world.
- Worlds/departments must have their own local meaning and local layout.
- The screenshots are partial mental models, not full UIs to clone.
- Hermes is the agentic-system reference, not the whole QMX layout.
- Fincept contributes a different layout principle from aesthetics.
- Agents are part of the eventual product and cannot be ignored in layout architecture.
- Human work remains primary enough that QMX is usable directly without forcing every action through chat.
- Library and Trading Node must not become duplicated records across departments.

## Inferred but not yet approved

- Agent lanes exist in every major world, with mode-specific placement.
- Agent Hub exists as a full-world view for cross-session supervision, history, capabilities, artifacts and scheduled jobs.
- Plan/Act-style controls are useful but must be renamed or redesigned around QMX's safety model before approval.
- Cost/usage/run state should be visible because long-running agents can consume compute and money.
- Pairing two worlds is useful but should be optional and saved as a layout arrangement.

## Not supported

- A permanent universal right-side assistant dock as the answer.
- One repeated sidebar/table/details layout for all worlds.
- Treating five roles as five fixed top tabs before the department/world taxonomy is settled.
- Treating aesthetics as the issue. The issue is working grammar.
- Cloning Fincept, Hermes or RoboQuant wholesale.
- Making agents live-only, chat-only, or detached from exact selected object/version/context.
