## 3. Risk gates and priority assertions

The epic-specific centre of gravity. The synthetic subsystem's entire safety rests on the L20 firewall (nothing synthetic validates edge) and the B-7/AR-33 taint machinery (synthetic data can never masquerade as real evidence on the money path). Three **confirmed advisory findings** already breach that perimeter at three distinct doors; each gets a regression pin that is authored to **pin the correct behaviour** and is **expected to FAIL** against current source — the failure IS the evidence, never a licence to soften the assertion.

**R-006 — API-door parity gap (the synthetic capability is CLI-only).** *(confirmed finding F-23-01)*
B-1 is the single-library / thin-doors law: every capability exists exactly once in the library and is reachable identically from every door, proven by the tier-2 door-parity contract test (Epic 16). **Confirmed:** the `qmb data generate` synthetic-generation capability is exposed on the CLI door but **absent from the Python API door** — a parity break that lets an agent using the in-process API reach a *different* platform than the operator on the CLI, exactly the drift B-1 exists to prevent. **This finding is jointly owned with Epic 16's derived-parity test** (`T-16.5-a`/`-b` — "a capability present in one door but absent in the other FAILS"): Epic 16 owns the *parity mechanism*; Epic 23 pins the *specific missing capability*.
Covered by: **T23-PIN-01** — enumerate the generate capability through **both** doors' derived surfaces (the same programmatic enumeration Epic 16 uses, never a hand-list) and assert it is present in both; a CLI-only capability diverges the two computed sets and FAILS. **Expected to FAIL → records F-23-01.** *(EPIC-BINDING: FR-046/door-parity mechanism = Epic 16; this pin asserts only the synthetic capability's presence in both surfaces and hands the divergence to Epic 16's contract test — §7.1.)*

**R-007 — source-scale trust (the generator trusts the cited source dataset's declared scale).** *(confirmed finding F-23-02)*
CT-10/DEC-0105 is explicit: foreign money is stored verbatim as scaled integers **at the source's declared scale**, and "conversions to Money or Price are derived with lineage, **never a silent rescale**." A history-seeded generator (`block-bootstrap`/`gaussian-resample`/`gaussian-noise`) reads a cited `source-dataset id` (CT-10 room) and must produce prices **quantized to the *target instrument's* tick size** (AC 23.1.3 / R6) — which means the source's declared scale must be **converted through the named AD-7/AD-22 boundary** to the target's Price scale, never trusted and reused as-is. **Confirmed:** the generator trusts the source's declared scale (reuses it directly / silently rescales) instead of routing through the named conversion, so a source dataset whose scale differs from the target instrument's tick produces mis-scaled synthetic prices with no refusal.
Covered by: **T23-PIN-02** — feed a cited source dataset whose **declared scale differs** from the target instrument's tick scale and assert either (a) the synthetic prices are quantized to the **target** tick via the **named AD-7/AD-22 conversion** (lineage-carrying, declared rounding), never the source scale silently reused; **or** (b) a scale-incompatible source returns a typed **`invalid input`** refusal — **never a silent rescale** (DEC-0105). **Expected to FAIL → records F-23-02.** Reinforces R6 (T23-303).

**R-008 — nested-config replay-clock bypass (the world/clock guard is evaded when the binding is nested).** *(confirmed finding F-23-03)*
B-7 states a clock/adapter-vs-provenance mismatch is `invalid input`, and `qmb/FAILURES.md` FR-17 documents the designed guard: *"`bind_execution_ports` checks clock and provenance before looking up adapters … Replay-on-synthetic is invalid input because B-7 wins."* AC 23.3.3 requires config **compilation** to refuse a replay clock bound to synthetic-tainted data. **Confirmed:** the guard fires at the top-level composition root but is **bypassed when the replay-clock binding to synthetic-tainted data is nested** inside a composed / sub-config (e.g. a walk-forward window config, an optimization-study leg, a nested run-config fragment) — the compilation check does not recurse into the nested binding, so a nested replay-on-synthetic composition compiles instead of refusing. This is the highest-severity finding: it re-opens the exact synthetic-on-money-path backdoor B-7 closes.
Covered by: **T23-PIN-03** — construct a resolved run-config that binds a replay clock (or replay/live adapters) to synthetic-tainted data **through a nested/composed config path** (not the top-level binding) and assert config **compilation returns a typed `invalid input` refusal** (B-7 wins over B-2), identical to the top-level case. **Expected to FAIL → records F-23-03.** Reinforced by T23-314 (the top-level guard, which must also return not raise) and T23-317 (the namespace-write refusal the bypass would defeat).

**L20 / AR-33 / SC-06 firewall (structurally P0 across the epic, not a single row).** Nothing synthetic validates edge (L20): claim class `infra-stress`/`robustness`/`logic-smoke` only, never edge/alpha/validation; no verdict-bearing claim ships while GAP-0048 is open (SC-06); a `world=simulated` write into a governed/live namespace refuses (AR-33); synthetic artifacts are non-promotable and the world is provenance-derived, never caller-declared (B-7).
Covered by: **T23-308** (edge/alpha/validation refusal under any process), **T23-307/T23-322** (claim class bounded by lineage; from-scratch `gbm` cannot emit `robustness` or a band), **T23-310** (no verdict-bearing claim while GAP-0048 open), **T23-312/T23-313** (store-level `origin=synthetic` record; provenance-derived `world=simulated`), **T23-315** (non-promotable refusal), **T23-317** (never writes the governed/live namespace, AR-33).
