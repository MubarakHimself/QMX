## What works

Paradigm is a real contract: **composition kit over the four application-layer products plus QMF**, not a sixth COMP, not n8n/Hermes/OpenBB/LEAN as a runtime, not a marketplace. Experimentation Board is a working-surface projection. Capability / extension / workflow / mini-app / widget stay related, not a compulsory hierarchy.

- **Inherited table** binds constitution, Workbench, QMA, mill (selected), QMB, NODE/CONNECT, and graveyard DECs by original ids. Conflict examples (sixth COMP, Stage 0 graph as executor, QMA `import qmb`, dummy Book, json-render as identity) are named as conflicts, not overrides. Proposed parent amendments 1, 4, 5 are the right shape (Board alias; Portfolio Manager **label**; L36 not amended here).
- **AD-1 / AD-20** keep QMF as toolbox; ship defaults without empty-canvas or everything-is-a-node. Permanent extra process besides `qma-daemon`, `qmn`, and QMB process-per-run children is a spine amendment.
- **AD-4 / AD-6 / AD-7** split Board layout / Graph Template DAG / Task Graph / ungoverned library call. Stage 0 `graph` is none of these. Skills never compile to Missions. Runtime Loops stay node state. Reuse QMA Mission Compiler + RoutineScheduler + CT-47 occupancy. ExperimentSpec successors remain lineage, not control-flow. The pairwise-topology hole and dropped Task Graph edges are named as connect-in-place, which matches `validate_graph_template_topology` and in-memory `TaskGraphStore` @ 270e992.
- **AD-9 / AD-10 / AD-18** put copilot tool availability on published hits ∩ host grants ∩ session profile ∩ health; skill text cannot self-grant; model-authored hooks cannot override a failed deterministic check. Four composition modes are named; invocation cycles need a budget; template topology remains a DAG. Packs fail-closed on missing deps (do not copy Hermes warning-and-continue). DEC-0361 stays dead.
- **AD-11 / AD-14** keep default Book/BMS evaluable (regression first) and refuse dummy Book/BMS/MIS. Live/node-paper without Book is refused until an L36 amendment. Sequential stopped/flat-or-drained handover is the default; software rollback cannot undo fills; HMR stays dead (DEC-0366).
- **AD-12 / AD-13 / AD-16** wrap qmf-data; provider ≠ venue; preview ≠ export ≠ stream; source disagreement preserved; recipes are not a Library kind. Semantic identity stays fp1 / `research_ref` / `qualified_id` / ExperimentSpec / `composition_fp`. Evidence stays out of qmf-core; QMB JSONL unmerged; Graph Templates rebuild from plugins.
- **AD-17 / AD-19 / AD-21 / AD-22** put UI contribution DTOs on the wire now, chrome as GAP-0081; json-render and MCP Apps present registered views only; mutmut is optional test-strength on disposable WSL/POSIX copies, never a product dep, never `mutmut apply` on shared trees; QMB remains the operator CLI; Portfolio Manager is a label (`desk_slug=pm` until GAP-0083).
- **Deferred table** is mostly the right park: GAP-0081 chrome, C-05 L36, F07, GAP-0058/0062 *machine*, GAP-0063/0085, MemoryProvider engine, browser/desktop fail-closed, marketplace/solver, HMR, mutmut CI, presentation pins, slug rename, hypothesis listing, wire listener dispatch.

A third unit can also grow `qmb.library.search` to return contributions because AD-2 never restates COMP-QMA-WIRE as facade owner.

All three obey “not a fourth store,” “never a door **run**,” “kinds unchanged,” and “hypothesis refused on the facade.” What diverges: the frozen DTO, the owner, whether Story 52.1’s two-class freeze is amended or bypassed, and whether Artifact Library chrome is allowed to mean three hit classes.

Capability discovery is this sitting’s job. The defect is form plus uniqueness: mill AD-9’s “exactly two” is not in the proposed-parent-amendment list, AD-2’s “Frozen” overstates the live two-class freeze, and the concatenate owner is only in the capability map / structural seed, not in the Rule.

#### H-2 — AD-3 puts “cardinality/mapping” on the operation descriptor; AD-5 declares mapping on the edge

**Where:** AD-3 Rule (“output **shape** …, cardinality/mapping, effect class …”); AD-5 Rule (“Collection mapping is declared on the edge: `one` \| `zip` \| `broadcast` \| `keyed-join` \| `cartesian`”); INT-05; AD-5 Prevents (“guessed zip vs broadcast vs keyed join vs Cartesian”).

**Two conforming units**

- **Unit A — edge-law epic.** Every Graph Template edge must carry an explicit mapping. Missing mapping refuses at AD-6 validation. Cartesian requires the flag. Operation descriptors do not carry mapping.
- **Unit B — descriptor-default epic.** Reads AD-3 literally. Mapping is a field of the AD-3 descriptor (companion `CONTRACTS.md` already puts `"cardinality": "one"` and `"mapping": "one"` on the op). Edges without mapping inherit the op default. Zip vs broadcast is guessed from the producer’s cardinality.

Both prevent a *silent Cartesian* only if the other Rule is ignored. AD-5’s stated divergence is guessed combination. AD-3 re-opens it by giving mapping a second home.

Charitable intent: operations declare port **cardinality** (`one` \| `many` \| `stream`); edges declare **combination**. The spine writes them as one phrase.

**Action:** autofix. Split the nouns:

- AD-3: descriptor carries input/output **cardinality** (`one` \| `many` \| `stream`) plus the already-closed output **shape** and **effect class**. No mapping field on the op.
- AD-5: mapping is required on the edge; missing mapping refuses; Cartesian remains an explicit flag; empty-policy stays on the operation.

#### H-3 — `product_session` is named as a closed-store addition; its store class, journal fold, and AD-27 backup membership are not

**Where:** AD-8 Rule (“host/wire records distinct from QMA Session”); AD-16 Rule (persist in **COMP-QMA-DAEMON sqlite** as named additions); proposed parent amendment 3; QMA AD-6 (“A store not on this list may not be created”; Session records are **journal-derived projections**); QMA AD-8 ownership table; QMA AD-27 backup of **seven** daemon-owned stores (journal, three ledgers, artifact, staging, telemetry — not an unnamed extra sqlite table); AD-7 also persists “occupancy maps” which amendment 3 does **not** name; assignment: copilot + ops envelope.

**Two conforming units**

- **Unit A — QMA-law epic.** `product_session` is a journal-derived projection over `product_session.*` events, daemon sole writer, fold contract (`journal_seq`, `as_of` over `recorded_at`), rebuilt from the journal, retained with the journal, therefore in AD-27 because the journal is. Occupancy stays `environment_lease` / Workbench AD-8 run-vs-query; it is not a new store.
- **Unit B — extra-table epic.** AD-16 said sqlite, so add tables. No journal events, no announcement, no AD-27 membership. Daemon restart in-process may restore; off-machine restore does not. Occupancy maps become a third table (illegal under QMA AD-6 unless amended, or silently in-memory despite AD-7).

AD-8’s Prevents (tab-switch, app-use editing implementation, one global Agent) still hold. They do not prevent two durability classes. Copilot grants, account scope, and installed-instance binding are the authority overlay this sitting exists to mint. A session that does not survive the backup the rest of QMA already owes is an ops-envelope miss at this altitude.

QMA AD-12 already names Task Graph state; amendment 3 correctly says *persist the already-named projection*. `product_session` is the actually-new record. Occupancy maps are a second unclassed add.

**Action:** autofix.

1. `product_session` **is** a journal-derived projection (same class as Session/Agent records), daemon sole writer, `_ref` only, rebuilt from the journal, kept as long as the journal (AD-27). Not qmf-core. Not Memory. Not Knowledge. Not telemetry.
2. Wire DTO (AD-8) is the query/command shape of that projection; it is not client-only attachment state (contrast QMA AD-14 attachment).
3. Occupancy maps are **not** a new store: run occupancy remains Workbench AD-8 / QMA AD-17 `environment_lease`. Strike “occupancy maps” from AD-7 persist-list or name them as fields of the already-named Task Graph / lease projections.
4. Private notes (AD-9) either ride `product_session` as a scoped field **or** get an explicit Deferred row. They must not land in MemoryProvider or Knowledge.

#### H-4 — AD-8 “change-request staging artifact” collides with QMA AD-22’s closed staging law

**Where:** AD-8 Rule (“mint a **change-request** staging artifact”); companion `CONTRACTS.md` §4 (“Lands in QMA staging; apply is operator/authoring — never `promote`”); QMA AD-22 (staging store has **exactly one** record type, the RefinementProposal; edit kinds are a closed set: `prompt`, `memory`, `skill`, `toolset`, `worker_template`, `hook`, `graph_template`, `loop`, `role`; applied, never promoted); J01; assignment: copilot / app-use.

**Two conforming units**

- **Unit A — AD-22 epic.** Adds a `change_request` / `app` edit kind, or a second staging record type, so app-use can “stage.” That silently opens QMA AD-22 and can look like app-use editing definition-store or package source (the thing AD-8 Prevents).
- **Unit B — handoff-artifact epic.** Change-request is a content-addressed artifact-store record (CT-06 envelope) cited by the app-use session; a new authoring session opens with scoped refs; v1 instance and grants unchanged. Not a RefinementProposal. Not promote (L17). Not an AD-22 kind.

J01 is one of the sitting’s four proofs. “Staging artifact” plus the companion’s “QMA staging” makes Unit A the literal reading. Parent law makes Unit A a conflict. The spine does not pick Unit B in the Rule.

**Action:** autofix. In AD-8: a change-request **is** an artifact-store record (content-addressed, lineage to the app instance + target refs). It is **not** an AD-22 RefinementProposal, not a new staging record type, and not `promote`. Apply = operator opens a **new** authoring product session with those refs. App-use still must not edit package source, install, elevate grants, or retarget accounts. Tag no parent amendment unless a later sitting truly needs an AD-22 kind.
