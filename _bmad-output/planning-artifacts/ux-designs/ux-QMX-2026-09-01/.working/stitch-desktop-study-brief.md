# QMX desktop study — exploratory

Status: proposed interaction study, not an approved design.

Create ONE coherent desktop application design study for QMX (QuantMindX), a quantitative research, Python development and multi-asset trading work environment where humans and agents share tools and work. Produce THREE related desktop screens, each 1600 x 1000, showing successive states of the SAME task. This is a spatial/interaction study, not a marketing page or generic analytics dashboard.

Core direction: Bloomberg Launchpad's saved workspaces and linked tool panels, combined with Manus's substantial agent conversation alongside files and working output. A compact global launcher at extreme left opens complete environments as browser-like tabs across the top. Each environment has its own meaningful interior. Hermes is an agent environment, not the universal template for every environment. The user can also work directly in Python, data or charts without starting a conversation.

CONSISTENT OUTER SHELL in all three screens: restrained narrow dark global rail (QMX, launcher, Library, Runs, settings), browser-like open environment tabs 'Hermes / Liquidity study', 'Research / Cross-market', 'Markets', plus New environment. Clear active tab. Lightweight bottom status line with background run count. Do not duplicate this with a large generic global sidebar. Library holds shared datasets, code and versioned results. A saved layout selector, Add tool and small link-group indicators belong to the working environment. Use a composed, professional desktop visual language: graphite/ink navigation, light warm-gray working surfaces, fine separators, readable dense text, restrained blue highlights. No decorative gradients, enormous KPI cards, fake branding imagery, or rounded-card grid. Typography and color are provisional; the important design problem is hierarchy and usable space.

SCREEN 1 — Agent briefing. Active Hermes tab. A real substantial agent workspace, with a compact local sidebar containing sessions, files and scheduled work. Main conversation is spacious and readable, with an attached context strip that identifies the exact selected project, dataset snapshot and Python file. Example human message: 'Investigate whether this momentum signal survives realistic costs across BTC, EUR/USD and SPY. Compare the regimes and show me where it fails.' Agent responds with a short plan and linked context: momentum.py v12, daily-bars snapshot Sep 10, fees_baseline.yaml. Clear 'Open workbench' action. Composer stays at bottom; agent capabilities and attached scope are understandable. This is not an empty welcome screen. No invented reasoning transcript.

SCREEN 2 — Working alongside. Same task and Hermes session, workbench expanded. Compact local session navigation can collapse. Agent conversation occupies a usable left third; the right two thirds contain a Bloomberg-like arrangement of tools with independent title bars, maximize and local tabs: Python editor showing momentum.py, results comparison table below it, chart in the adjoining column. Linked selection: EUR/USD appears selected in results and highlighted in chart; BTC and SPY remain comparison context, not replaced globally. Show link group A in the linked panels. Table columns: variant, asset, sample, return, drawdown, turnover, cost assumptions. Values clearly illustrative. An agent action 'Cost sensitivity run R-024 running: 18 / 36 cases' links to the run. Visible 'Continue in background' control. User can edit code or inspect a result directly. Keep code and data legible and give tools real working area. Show a saved layout named 'Compare & inspect'.

SCREEN 3 — Return to results. Active Research / Cross-market tab. Same run R-024 now needs review and retains a link back to its Hermes conversation. Research environment has its own local project/files navigation; it is not merely the Hermes screen with renamed heading. Main area compares baseline and higher-cost results, with chart and dense table. A docked run inspector shows named steps, outputs with versions, and a concrete finding: 'EUR/USD loses its advantage under higher costs; BTC and SPY require out-of-sample review.' Show 36/36 cases completed, elapsed time, inputs, source version, inspect logs, and Open conversation. Review is an explicit user decision; no automated trade deployment. Small global run indicator confirms other work may continue while navigating. Do not make all agent activity require a visual workflow graph.

Use identical task names, outer navigation and data semantics throughout. Labels should be product language, no infrastructure or implementation jargon. All market values are fictional demonstration data, marked 'Illustrative data' unobtrusively. Deliver these as three separate, named screens in a single project: '01 Brief the agent', '02 Work alongside', '03 Review the run'. Prioritize a believable everyday desktop work environment and the transitions between these screens. Do not design mobile layouts. Do not add extra screens or a design-system page.
