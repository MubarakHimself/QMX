# ADR-0018: QML — the bot-authoring library

Date: 2026-08-21. Status: provisional pending operator ratification of the corpus. The design itself is ratified by operator delegation (2026-08-21, spine QL-1..QL-10 FINAL — DEC-0184).

## Context

The corpus has carried QML as a named-but-empty slot since the first foundation sitting: QMF is the framework umbrella and QML names the future Bot-oriented library rather than the whole foundation (DEC-0017, constitution L11). The V1 roster then deferred it explicitly — the QML Bot library is outside the QMF V1 roster **until its Bot-to-Book binding contract is designed** (DEC-0090, ADR-0011). That condition is now met. The ratified QMF spine supplies the binding chain and authority order (AD-29), the template discipline whose two `pending(GAP-0047)` slots were reserved for this sitting (AD-30), the admission bar and prediction-linter Layer-1 slot (AD-32), the exit-ownership and `ExitLogicRef` provenance flag (AD-33), and the CT-28 binding context; the QMB sitting added the run-config, ledger, and parameter-space machinery (B-3, B-4, B-8, B-12) a bot layer plugs into. GAP-0047 — QML the bot-authoring layer: Bot schema (AD-16's reserved kind), confluence composition (AD-17), family keying, admission-bar interfaces, the plain-Python-vs-`.qml` ruling, and build order — was the last open question the binding contract's arrival unblocked.

Two inputs grounded the sitting, both cite-only structural evidence under the corpus's named exemption (QMX-discussion is barred for risk/sizing; QML structural definitions are citable): the QML original-dig dossier and the QML dig-verification dossier. The old QML is **evidence and shape only, never code** — its risk/sizing content is superseded by AD-29..AD-41 — and the dig-verification dossier is what raised the mandatory plain-Python-vs-`.qml`-DSL question. The operator's ordering lead (recorded in ADR-0017's consequences) permitted the QML sitting to run before the backtesting-content sitting.

The sitting ran **autonomously by operator delegation** on 2026-08-21 (verbatim intent: "try to run this without me... close this out as smoothly and as simply as possible, but be thorough"), with every without-operator call tagged in the memlog and individually overturnable. It produced the child spine QL-1..QL-10 (FINAL) and passed a five-lens reviewer gate at desk — rubric, adversarial, currency/reality, inputs-reconcile, and parent-consistency — 34 findings, all applied (the headline being the reversal of the draft entry-intent derivation to the Book-side single-sited design). Ratification arrived by delegation the same day (DEC-0184).

## Options considered

1. **Revive QML as a cross-component contract layer** (the old load-bearing stratum that sat under every component). Rejected as the old failure the prior generation already retired: QMF's contracts are the shared layer now, and the old uniformity rationale — "compare bots honestly, same deterministic risk authority, same formula" — is **already delivered by ratified QMF law** (CT-23 Book-resolved sizing, AD-40 frozen R, CT-29/CT-32 containers). Rebuilding a private contract stratum would duplicate the umbrella and re-create the coupling that killed the first QML (DEC-0171).
2. **Revive the `.qml` DSL and Monaco file format** as a second authoring language. Rejected (DEC-0172): a second language is a second grammar to maintain and govern, and plain Python stays first-class forever under the operator's standing direction and the build-our-own economy. What the old `.qml` file carried (entry, filters, gates, subscriptions as editable source) is delivered by the declaration (structure) plus the Python logic (conditions). A future declarative condition grammar, editor surface, or agent-codegen lane compiles to the **same two artifacts** — nothing forecloses it, nothing waits on it.
3. **Fold bot authoring into `qmf-registry`, or into QMB.** Rejected on authority grounds. `qmf-registry` owns record kinds and lineage, never authoring semantics or a runtime protocol — the CT-33/CT-34 author types, the footprint/template resolution, the bot runtime protocol, and the conformance verdict function are not registry concerns. QMB is the experimentation **host**: it consumes bots and must not author or gate them, exactly as the door/library law keeps QMB publishing while the Book door and operator act (B-1). Neither can hold the authoring surface without inverting a fence.
4. **Build QML as a thin authoring library** — one uv-installable application-layer distribution on QMF whose whole surface is three thin things: author-side types/helpers for the Bot-domain registry artifacts (CT-33/CT-34), the bot runtime protocol hosts invoke, and the conformance gate. Selected (DEC-0171..DEC-0184).

## Decision

QML is the QMX bot-authoring product: **one uv-installable distribution (`import qml`), an application-layer library built ON QMF exactly as QMB is** (AD-2, L11), never a QMF roster package, never a framework, never an engine, and never again a cross-component contract layer. Its surface is three thin things and no more — author-side types/helpers producing the Bot-domain registry artifacts on `qmf-core` nouns, the bot runtime protocol, and the conformance gate — and **QML mints no new QMF-ladder (`CT-*`) shared contract of its own**: CT-33/CT-34 are `qmf-registry` kinds this sitting fills, and the runtime protocol and conformance contract are QML-local contracts on QML's own AD-5 format-version ladder. Plain Python stays first-class forever: an unregistered bot needs zero QML imports to run in QMB or research, and conformance is the ticket into governed evidence and Book seats, nothing else. No acronym expansion is minted (the L reads as *Library*). QML imports `qmf-core`, `qmf-registry`, and `qmf-risk` (CT-23/CT-29 types) and **never `qmf-venue`**; the default-deny dependency-direction rule is read roster-scoped, the reading the QMB precedent already exercises, recorded as a declared reconciliation note at source (DEC-0171, DEC-0169).

A governed bot is exactly **two artifacts**: the **declaration** (a structured configuration artifact under AD-30's template discipline, registered as the CT-33 Bot definition) and the **logic** (plain Python conforming to the runtime protocol, a versioned distribution whose identity basis is distribution identity + version + a canonical **source-manifest fingerprint** — never non-reproducible wheel bytes — and these are identity fields of the Bot definition, so a code change mints a new Bot exactly as a changed number mints a new Book). The `.qml` DSL is not revived in V1 (DEC-0172).

- **CT-33 Bot definition** fills AD-16's reserved Bot kind — a `qmf-registry` per-kind contract, authored via QML, owned by `qmf-registry`. The AD-16 header's writer/sequence/stable-id/created-at are ordering/occurrence fields excluded from `fp1`; Bot identity is semantic content plus the contract format version and at-birth refs, in six groups: exactly one strategy-family id; the confluence set (one-or-more CT-34 fingerprints, canonically ordered by child fingerprint with display-only ordinals); the declared parameter space — B-8's schema **completed with the AD-40 unit-kind every variable already requires, one schema never two**, whose mandatory defaults form the **canonical assignment**; the footprint (which contains the stream-set declaration as one locus); the permitted-intent declaration (`entry` always permitted; the named permitted **exit**-intent kinds a subset of the ratified CT-23 vocabulary, which may be empty, stored as opaque `qmf-core`-typed values so `qmf-registry` gains no `qmf-risk` edge); and the logic reference. Versioning is AD-30's git logic verbatim (append-only `branches-from` graph, dated current pointer, `continues-performance` human-signed). **Parameterization law:** governed live/paper seats execute the canonical assignment only; non-default assignments exist solely as B-3 run-spec overrides in experimentation; promoting a tuned assignment mints a new Bot version, so no tuned bot silently wears the original's track record (DEC-0173).
- **Footprint** is the single canonical consumption manifest — stream set, required calendars (AD-8 identities + versions), and producer bindings each either a pinned CT-16/CT-17 fingerprint or a producer **template** (a complete CT-16/CT-17 configuration minus only the space-bound values; an omitted identity field is a Layer-1 refusal; resolution is a total, single-valued function to one deterministic fingerprint). The producer-binding set MUST equal the transitive union of every cited confluence's leg producers plus bot-direct producers (a missing one is a Layer-1 refusal); hosts provide only the declared footprint; the warm-up/embargo horizon is derived at resolution from the producer chain, never hand-declared. Book-side `footprint_requirements` gains its shape: a set of typed requirements over CT-33 footprint fields under `admission_bar`'s grammar, values in Book templates only (DEC-0174).
- **CT-34 confluence** is its own registry artifact, reusable and cited by fingerprint: one-or-more legs of any role mix, each leg `(role, producer binding, optional exact parameters)`, a leg may cite another confluence. The leg-role vocabulary is CT-34's own closed-and-addable surface — `level | trigger | confirmation | filter` — with AD-17's three the seed and `filter` the first addition (freshly minted, provenance-marked): a suppressing condition on the same governed producers. Legs follow AD-17's fingerprint-ascending default (a confluence is not a CT-17 causal composite, so AD-25's order-significant-by-default does not reach it); order-significance is opt-in and enters the fingerprint only when declared. Condition semantics live in logic in V1; a declarative predicate grammar is Deferred (DEC-0175).
- **Strategy family** is an opaque operator-minted id plus a dated registry metadata record — the same machinery as `instrument_class`, a kind under CT-06's addable-kinds law with no new CT number — and it is a **keying token with no authority**. Every Bot definition declares exactly one family (a deliberate AD-17 cardinality-one ruling); a Book's `exit_policy` keys by family and may declare one catch-all default entry; a bot whose family resolves no entry fails the prediction linter. The old ArchetypeSpec's constraint powers are not revived; "archetype" is the retired alias (DEC-0176).
- **The bot runtime protocol** is a QML-owned format-versioned contract on QML's own AD-5 ladder. A conformant bot is a factory the host constructs with `(declaration, resolved assignment, injected read surfaces)`, returning a callback the host drives per evaluation instant; callbacks receive only declared-footprint evidence and return zero-or-more CT-23 intents. The bot never sizes, never touches venue commands, never reads a clock, never performs I/O/network/undeclared randomness; conformant logic is deterministic (B-2's golden-slice property). The entry proposal carries an **advisory stop proposal** (a proposed protective-stop price or `PriceDelta` bound, advisory exactly as `proposed_r` is); the **declared full-loss price is derived Book-side at the door**, single-sited, by the Book executing its own per-family `ExitLogicRef` and stamping the price exactly as it resolves `requested_r` — no Book module is ever injected into bot logic (DEC-0177).
- **The conformance gate** is technical, never performance. Layer 1 is the declaration linter at registration (schema/unit-kind/reference/footprint/template completeness, exit-intent kinds within the ratified CT-23 vocabulary; failures are AD-11 typed refusals). Layer 2 is sandboxed execution conformance split into a QML-owned pure contract (denial set, static AST/import scan, determinism harness, deterministic golden-slice generator keyed off the footprint, verdict function) and a host-owned process runner — so a verdict is host-independent by construction and no Book is present. **The ticket:** the Bot kind mints only on passing both layers, and that registration is what governed evidence and seats cite; ungoverned bots keep full tunnel access — conformance gates evidence **citation** and **seats**, never tunnel entry. The prediction linter's four pinned checks fill AD-32's Layer-1 slot (footprint satisfies the Book's `footprint_requirements`; declared exit-intent kinds subset the Book's permitted exit kinds; the family resolves an `exit_policy` entry; the stream set lies within declared venue capabilities). The admission-bar interfaces land only through the CT-22 format mint (interfaces only; thresholds stay GAP-0048/0049). The old `max_acceptable_complexity_score` gate is not revived — a stated drop (DEC-0178).
- **Exit reconciliation** closes AD-33's provenance flag by ratifying the donor atoms as-is: `ExitLogicRef` stays in the Book's `exit_policy` per family, the Bot definition carries no `exit_logic` field, and CT-29's typed close-reason taxonomy stays the one taxonomy with the old `CloseReason` members recorded as an evidence mapping, never a second contract (DEC-0179, DEC-0024 lineage honored).
- **Build order:** QML builds before the trading node and may build alongside QMB (it consumes QMF contracts only; nothing waits on node runtime); QMB exercises plain-Python bots day one and conformant bots the day QML lands; the node hosts seats later. The `qml` distribution carries its own SemVer as display-only provenance, consumes the QMF workspace in lockstep, and installs as a normal pinned dependency (`uv add qml`) (DEC-0180).
- **Parent-contract mints** the sitting could not make by assertion: **CT-22 format version 2** (admission-bar's `evidence_requirements` +2 bot-side fields; `exit_policy`'s one explicit optional catch-all with the CT-29 exit record keying the resolved entry; `footprint_requirements`' reserved pending slot filled) and **CT-23 format version 2** (the advisory stop proposal as one new optional entry field; the full-loss price documented Book-resolved) — both AD-5 format-version mints owned by `qmf-risk` with QML-authored semantics, migration notes mandatory, pre-mint artifacts readable forever (DEC-0181, DEC-0182). Three QMB sibling-coordination items are declared, not silent (DEC-0183). The spine QL-1..QL-10 is adopted in full and GAP-0047 is answered (DEC-0184).

## Architecture-preflight verdict

**new `COMP-QML`** — with the inventory read and every reuse candidate named and refused by ID:

- **`COMP-QMF-REGISTRY`** owns record kinds and lineage and will own CT-33/CT-34 as kinds, but it is a records boundary — it never carries authoring semantics or a runtime protocol. The author-side types and canonical ordering, the footprint producer-binding and template resolution, the bot runtime protocol, and the conformance verdict function are not registry concerns; a records package cannot host a protocol hosts invoke per evaluation instant (authority boundary).
- **`COMP-QMF-RISK`** owns the Book-side definitions QML consumes read-only (CT-22 admission bar and `exit_policy`, CT-23 intents, CT-29 close reasons), but it is a definitions boundary forbidden from running anything. The **bot side must stay import-legal for applications**, and `qmf-risk` must not gain an authoring surface — folding bot authoring into it would force applications to reach an authoring stratum through a definitions package and invert the boundary. The two format-version mints QML needs are owned by `qmf-risk` and authored by QML precisely so the definitions stay where they are.
- **`COMP-QMB`** is the experimentation host: it consumes bots (plain-Python today, conformant through a runtime-protocol adapter at its composition root the day QML lands) and must not author or gate them. The door/library law keeps the host from owning the artifact it hosts — QMB publishes but never benches, promotes, or binds (B-1) — so the authoring library and its conformance gate cannot live inside QMB.
- **`COMP-QMF-CORE`** is a framework-neutral definitions-only library that must contain no broker, event loop, backtest, download, or trading-node runtime (L13, DEC-0022). It supplies the nouns, fingerprints, refusals, and series vocabulary QML builds on, and cannot own an application-layer authoring library.
- **Dead-list check.** DEC-0090 deferred the QML Bot library outside the QMF V1 roster **until its Bot-to-Book binding contract was designed** — that condition is now met (AD-29 binding chain, AD-30 template discipline with its reserved pending slots, AD-32 admission bar, AD-33 exit ownership, CT-28 binding context), so realizing `COMP-QML` **honors the deferral rather than revives it; the deferral was never a prohibition** (DEC-0090). The dead engine/service decisions stay dead and untouched: the central backtesting service (DEC-0084), Nautilus contract adoption (DEC-0085), and the adoption spike (DEC-0086). Two things the old QML carried are explicitly **not** revived — stated drops, decisions not omissions: the `.qml` DSL and its Monaco second-language surface (DEC-0172), and the `max_acceptable_complexity_score` registration gate (DEC-0178).

What `COMP-QML` owns that nothing else does: the author-side CT-33/CT-34 types, schema validation, and canonical ordering; the footprint producer-binding, template resolution, and horizon derivation helpers; the bot runtime protocol and its state snapshot/restore contract on QML's own AD-5 ladder; and the conformance contract — the Layer-1 linter, the pure Layer-2 verdict function, the deterministic golden-slice generator, and the prediction-linter checks. What it may never do: size (`requested_r` is Book-resolved), touch venue commands, read a clock, perform I/O/network below the host, import `qmf-venue`, own the Bot-kind record stream's write authority (the composition root holds the `WriterId`; `qmf-registry` owns the kind), or gate tunnel entry (conformance gates evidence citation and seats, never research-lane access). No existing component's authority shrinks: `qmf-registry` gains two kind bodies it **already reserved** (AD-16's Bot kind, AD-17's confluence composite); `qmf-risk` gains two format-version mints of contracts it already owns; QMB gains three declared sibling extensions at its composition root, not a re-architecture (DEC-0183). QML fills the slot the corpus had reserved empty (DEC-0017, DEC-0090) and is the first authoring library where the Bot-domain kinds become live.

## Consequences

- CT-33 (Bot definition) and CT-34 (confluence) mint as `qmf-registry` kinds; CT-06's reserved Bot kind body is now ruled via CT-33, and the strategy-family dated-metadata record lands as a new addable kind (no new CT number, no format change to CT-06 — the addable path).
- CT-22 and CT-23 each gain **format version 2** as AD-5 format-version mints owned by `qmf-risk` with QML-authored semantics; migration notes are mandatory, pre-mint artifacts stay readable forever, and a v1 reader confronting v2 refuses `unsupported capability` (DEC-0181, DEC-0182).
- QMB budgets for three declared sibling-coordination items recorded in its component doc: the B-3 `assignment_is_canonical` resolved-config stamp plus the B-4 fold qualifier that reads it; producer-template resolution as a B-3 config-compiler extension and a node seat-admission step; and B-8's parameter-space schema completed with unit-kinds (one CT-33-authoritative schema). None re-architects QMB (DEC-0183).
- Build order is settled: QML before the trading node, alongside QMB; QMB tests plain-Python bots as the bridge and binds conformant bots through the runtime-protocol adapter the day QML lands; the node hosts seats later (DEC-0180).
- The registration linter's raw material is now defined, but the registration/promotion **gate** stays deferred: GAP-0016/0017 (DEC-0121) is unchanged, and the admission-bar and prediction-linter **thresholds** stay GAP-0048 content and GAP-0049 — QL-8 ships the interfaces only, and blank requirements keep blocking live money. The conformance gate mints the Bot kind on technical pass; it is not the performance gate.
- Three operator questions are recorded non-blocking, none gating the build: a UI display name for the declaration artifact ("BotSpec" is the old word; the spine says "Bot definition"); a `qml` CLI convenience (V1 is library-only); and an NN/ML weights-artifact parameter kind (baked-in weights are governed today via logic-artifact identity — nothing refuses an NN bot; a separately-tunable weights kind is a later mint). Each tagged assumption is individually overturnable without unwinding another ruling (DEC-0184).
- Implementation authorization is unchanged: factory-pipeline-only, and the corpus stays provisional. Design is ratified by delegation; nothing here authorizes code.
- **Update 2026-08-21 (veto round):** the operator reviewed the six delegation-made calls (no-DSL-in-V1, the canonical-assignment parameterization law, `filter` as the fourth confluence leg role, family = key-not-authority, the advisory-stop/Book-side single-sited full-loss derivation, and the CT-33/CT-34 numbering) and **confirmed all of them kept**, none overturned. Two expansion riders are recorded, each an expansion inside an already-ratified shape rather than a contract-format change: a confluence leg may carry **both** a producer binding and a child-confluence cite (at least one required, the role mandatory, leg/component counts never bounded — CT-34), and a Book's per-family `ExitLogicRef` may declare an **adopt-the-bot's-advisory-stop** module mode so bot-owned exit methodologies are first-class (a declared module mode inside the existing `{module_id, config}` shape, `requested_r` still Book-resolved — CT-22). The `qml` CLI question is ruled — **no second command line**; QMB's `qmb` CLI is the single command-line surface. The CT-23 inbound-full-loss coordination question is resolved by the adoption mode (no inbound-refusal posture added); the CT-29 resolved-entry keying field shape stays operator-aligned deferred; and the UI display name for the declaration artifact stays open platform territory with the recorded read-only-when-live lean (a live bot's declaration surfaces read-only — an edit mints a new version — while an editable/config view belongs to research mode). The NN/ML weights-artifact kind stays a non-blocking open question. Each tagged assumption remained individually overturnable; none was (DEC-0185).
