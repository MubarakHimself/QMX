# Catalog Maps — awesome-quant, awesome-systematic-trading, EliteQuant, quant-wiki, Quant-Developers-Resources, quant-trading

**Written:** 2026-08-17. **Scope:** six catalog/list repos, not one production framework. The job here is different from the other studies: don't extract one framework's architecture — extract the *map*, classify what's on it, and surface the ~15 items the other nine studies plausibly missed.

---

## In plain words

1. These six repos are not trading software. Five of them are curated *lists* — link collections pointing at other people's code, books, blogs and data APIs. The sixth, `quant-trading`, is a personal collection of ~15 short, single-file teaching scripts.
2. `awesome-quant` is the one Mubarak was right about: it is a living map. It has ~500 entries, a working parser, a daily-refreshed website with GitHub star counts and last-commit dates, and it is being actively curated as of this week (entries dated 2026-08).
3. `awesome-systematic-trading` is a smaller, more curated cousin — 97 libraries, but also 40+ named strategies with backtested Sharpe ratios and citations to the original paper. Three of those strategies are pure currency-factor trades (FX carry, currency momentum, currency value/PPP).
4. `EliteQuant` is a dead-ish, ~2019-era link list. Its top entries point at Quantopian, which shut down in 2020, and IBridgePy/OpenQuant/RightEdge, most of which are stale or discontinued. It has no update mechanism and nothing here is worth returning to.
5. `quant-wiki` is a Chinese-language glossary and reading room (LLMQuant Team) — finance terminology, book pointers, industry-culture essays, interview prep. It is a dictionary, not an engineering reference. Its one relevant page (外汇/Forex) is a two-paragraph definition.
6. `Quant-Developers-Resources` is an interview-prep and topic-index repo (probability, stochastic calculus, C++, FPGA, poker theory, resume templates) plus a handful of tutorial-grade Jupyter projects (ARIMA+GARCH, pairs trading, LSTM forecasting). None of it is forex-specific or production-grade.
7. `quant-trading` (je-suis-tm) is real, runnable code — but it says so itself: "all trades are frictionless. No slippage, no surcharge, no illiquidity." It is teaching material for pattern recognition, not a system to build on.
8. Buried inside `awesome-quant`'s huge, noisy list are a small number of genuinely new, genuinely relevant finds: a risk-toolkit library that mirrors QMF's own sizing/gate split, a linter that catches look-ahead bias by replaying rules over history (exactly the `smartmoneyconcepts` bug the other studies flagged), and two multi-agent trading frameworks that already enforce "the LLM never has a direct order path" — the same rule QMF's design session landed on independently.
9. The catalog also confirms a negative: nobody in any of these six lists has a cTrader adapter, a prop-firm rule engine, or an honest support/demand-zone library. That gap is real, not a search failure.
10. For forex specifically, the pickings are thin but not empty: a Ruby OANDA framework (`Jiji`), a zero-dependency FX value-date calculator, a commercial multi-broker gateway (`TradeMux`) that validates the "one broker port, many venues" shape, and a scattering of MetaTrader/cTrader wrapper packages of wildly varying quality.
11. Net verdict: treat `awesome-quant` as a search index to re-run periodically (it updates daily), treat `awesome-systematic-trading`'s strategy table as a reading list with citations, and treat the other four repos as: one dead, one a dictionary, one an interview-prep index, one a teaching-scripts folder. None of the six is a dependency candidate.

## How it is built

This section documents structure, not architecture — these are content repos, not software.

### awesome-quant — `reference/repos/awesome-quant/`

- **Source of truth:** `README.md` (752 lines... actually 500 categorized entries across 18 `##` sections — see `AGENTS.md` line 8). Entry format is machine-parseable: `` - [name](url) - `Lang1` `Lang2` - description. `` (`AGENTS.md:20-46`).
- **Pipeline:** `parse.py` reads `README.md`, hits the GitHub API for stars/last-commit, writes `site/projects.csv` (499 rows, has a `last_commit` column with dates through 2026-03); `site/generate.py` turns that into a searchable static site deployed to GitHub Pages by `.github/workflows/build.yml` on a daily cron (`CLAUDE.md`).
- **This is an actively engineered, agent-maintained repo**, not a stale gist: it has `AGENTS.md`, `CLAUDE.md`, repo-scoped skills (`sprr`/`bprr` PR reviewers, `update-pypi-dates`), and a validation script (`scripts/validate_readme.py`) enforcing the entry format and catching duplicates.
- **18 sections** (`README.md:9-25`): Numerical Libraries & Data Structures, Financial Instruments & Pricing, Technical Indicators, Trading & Backtesting, Portfolio Optimization & Risk Analysis, Factor Analysis, Sentiment Analysis & Alternative Data, Time Series Analysis, Market Data & Data Sources, Prediction Markets, Calendars & Market Hours, Visualization, Excel Integration, Quant Research Environments, Cross-Language Frameworks, Reproducing Works/Training/Books, Commercial & Proprietary Services, Related Lists.
- **`quants.md` and `legacy.txt`** (`awesome-quant/quants.md`, 4 lines; `legacy.txt`, 28 lines) are near-empty leftovers from an older format — not load-bearing.

### awesome-systematic-trading — `reference/repos/awesome-systematic-trading/`

- Single `README.md` (578 lines), table-based, one row per project with a GitHub-star badge (`README.md:88-107` for the Backtesting/Live-Trading table). No parser, no CI, no automation — a static list maintained by paperswithbacktest.com (`README.md:24-26`).
- Two content types beyond libraries: (a) a **library table** (Backtesting, Analytics/Indicators/Metrics/Optimization/Pricing/Risk, Broker APIs, Data Sources, Databases, ML, Time Series, Visualization); (b) a **strategy table** with columns Sharpe / CAGR / Rebalancing frequency / code link / paper link, grouped by asset class (`README.md:53-64` contents, `313-364` for the currency-relevant rows).
- The strategy code lives in `static/strategies/*.py` and is written against QuantConnect's `AlgorithmImports` (Lean's Python API) plus a Quantpedia paid-data subscription (`static/strategies/fx-carry-trade.py:1-20` — imports `AlgorithmImports`, reads from `data.quantpedia.com/backtesting_data/...`). **Not runnable without a Quantpedia subscription and a Lean environment.**
- Currency-specific strategy rows (`README.md:357-364`): FX Carry Trade (Sharpe 0.254, CAGR 7.8%, monthly rebalance), Currency Momentum Factor (Sharpe -0.01, CAGR 6.7%, monthly), Currency Value Factor – PPP Strategy (Sharpe -0.103, CAGR 5%, quarterly). All three cite the same 2009 Deutsche Bank paper on currency returns. **Read as a documented literature pointer, not as backtest-ready code — and note the negative Sharpes on two of the three.**

### EliteQuant — `reference/repos/EliteQuant/`

- One `README.md` (515 lines), no build, no CI, no parser — a hand-maintained bullet list from roughly 2018–2019 (internal evidence: Quantopian, IBridgePy, RightEdge, SmartQuant/OpenQuant are all listed as live platforms; Quantopian shut down in August 2020). Sections: Quantitative Trading Platform, Trading System, Quantitative Library, Quantitative Model, Trading API, Data Source, Cryptocurrency, Companies, Fintech, Websites/Forums/Blogs (`README.md:8-16`).
- Its own top entry links to `awesome-quant` (`README.md:20`) — it is explicitly a sibling list, not a competitor.

### quant-wiki — `reference/repos/quant-wiki/`

- MkDocs site (`mkdocs.yml`), Chinese-language ("LLMQuant Team"), organized into 基本概念 (basic concepts/glossary), advanced/最新技术, ai (LLM-for-quant essays), industry (buy-side/sell-side culture), job (interview prep translations), library (book pointers under `docs/library/book/`).
- Confirmed via grep: exactly two glossary pages mention forex (`外汇_Forex.md`, `外汇市场_Foreign Exchange.md`) — short definitional entries, not domain engineering content. One page on backtesting concepts (`docs/basic/quant/回测_Backtesting.md`).
- This is a **dictionary and reading list**, not a code or design reference.

### Quant-Developers-Resources — `reference/repos/Quant-Developers-Resources/`

- Directory-per-topic structure, no README-as-index beyond a top-level bullet outline (`README.md:1-60`): interview-prep topics (mental math, brainteasers, probability, market-making games), then subject folders — `Artificial Intelligence`, `C++`, `Computer Architecture`, `CUDA`, `Credit Risk Modeling`, `Econometrics`, `FPGA`, `Game Theory`, `Mathematics`, `Optimization Theory`, `Poker Theory`, `Python`, `PyTorch`, `Quantum Computing`, `R`, `Reinforcement Learning`, `ResumeTemplates`.
- `Projects/` (`Projects/` listing) holds ~8 tutorial-grade single-topic folders: ARIMA+GARCH trading strategy, EMA+Bollinger automated strategy, cointegration pairs trading, Black-Scholes PDE derivation, LSTM forecasting, option-chain analyzer, sentiment-analysis trading strategy. Generic, not forex-specific, notebook-grade.
- This repo is **interview/career prep + generic ML-for-finance tutorials** — useful only as a training-material index, not for QMF's design.

### quant-trading — `reference/repos/quant-trading/`

- ~20 top-level single-file scripts, one strategy each, named directly (`London Breakout backtest.py`, `MACD Oscillator backtest.py`, `Pair trading backtest.py`, etc.), plus a few multi-file "project" folders (`Monte Carlo project`, `Oil Money project`, `Smart Farmers project`). `data/` holds the small CSVs each script reads (`gbpusd.csv`, `bitcoin.csv`, `treasury yield curve rates.csv`).
- **`London Breakout backtest.py` is directly forex-shaped** (286 lines): computes prior-hour Tokyo-session high/low as a threshold, trades the first 30 minutes of the London session, exits at a fixed target/stop or at session end (`London Breakout backtest.py:9-24` — the strategy description is literally written as inline comments). It hardcodes `os.chdir('d:/')` (`:44`) and reads one-minute histdata.com CSVs the author cleaned by hand.
- The README states the operating assumption up front: **"all scripts are historical data backtesting/forward testing... all trades are frictionless. No slippage, no surcharge, no illiquidity"** (`README.md:20`). That single sentence is the whole risk assessment needed for this repo: it is a *pattern library* for strategy logic, with zero execution realism.
- Licence: Apache-2.0 (per the task's licence table) — technically fine to read code directly, but it teaches vectorized-with-hindsight backtesting habits (no look-ahead guards visible in a skim of `london_breakout()`), which is exactly the failure mode the other QMF studies are trying to design *out* of the framework.

## Mental models worth borrowing

1. **A curated list that validates its own entries in CI is worth more than one that doesn't.** `awesome-quant`'s `scripts/validate_readme.py` (run in CI on every PR, per `AGENTS.md:26-33`) checks entry format, catches duplicate URLs, and flags "legacy" formatting as a warning. For QMF's own component registry (`qmf.registry` in the synthesis doc), the same idea applies directly: a registration is only as good as the validator that runs before it is accepted.
2. **Star count + last-commit date, computed automatically, beats a hand-maintained "maintained: yes/no" column.** `parse.py` hits the GitHub API and writes `last_commit`/`stars` into `site/projects.csv` on a daily cron. QMF's own confluence/model registry (Ring 8 in the synthesis map) could borrow this: a manifest field that's *computed*, not self-reported, for anything with an external dependency (e.g., "days since this data source's schema last matched what we ingest").
3. **State your backtest's fidelity assumption in one sentence, in the README, above the fold.** `quant-trading`'s "all trades are frictionless. No slippage, no surcharge, no illiquidity" (`README.md:20`) is a model of honest disclosure — one line, unavoidable, no fine print. QMF's `qmf.sim` module (Ring 6) should ship the equivalent: every backtest result object should carry a visible fidelity tag, not bury the frictionless assumption in code.
4. **A documented strategy table with Sharpe, CAGR, rebalance frequency and a paper citation, sitting next to the code, is a good shape for QMF's own "known ideas" reading list** — even when (especially when) the numbers are bad. `awesome-systematic-trading`'s currency-factor rows show a Sharpe of -0.01 and -0.103 right next to the paper link (`README.md:357-364`). That is the "evidence_state" idea from the synthesis doc, already in the wild: publish the negative result with the same visibility as a positive one.

## What to avoid

- **Don't treat "in awesome-quant" as "vetted."** The list accepts anything that passes the format regex; PR review (`sprr`/`bprr`) checks placement and duplicates, not quality or safety. Several 2025-26 entries are AI-agent trading wrappers with no evidence of live use (`AI Quant Agents`, `Orallexa`, `FinClaw` — self-reported "+29.1% annual alpha" with no audited track record, `README.md:194-230`). Read these as ideas, never as endorsements.
- **Don't clone `quant-trading` scripts into a backtest pipeline without adding execution realism.** They are explicitly frictionless, and a skim of `london_breakout()` shows no look-ahead guard on the signal generation loop — the exact bug class (`03`/`06` in the prior QMX research) that turned `smartmoneyconcepts`'s profit factor from 7.32 to 1.82 once corrected.
- **Don't use EliteQuant as a current reference for anything.** Its "Trading System" and "Quantitative Trading Platform" sections point at dead or dormant projects (Quantopian, several closed-source Windows apps with no changelog activity findable). Its only remaining value is as a historical index of what mattered in 2018-2019.
- **Don't mistake `quant-wiki`'s glossary entries for domain research.** The forex pages are dictionary-length definitions, not the kind of empirical finding (e.g., spread-cost-as-share-of-edge, causal zigzag lag) the other nine QMX studies already produced. Going back to `quant-wiki` for forex specifics would be a regression, not progress.
- **Don't run the QuantConnect-flavored strategy code in `awesome-systematic-trading/static/strategies/` expecting it to execute.** It imports `AlgorithmImports` (Lean-only) and reads from `data.quantpedia.com`, a paid subscription endpoint (`static/strategies/fx-carry-trade.py:1-20`). Useful as a documented factor-strategy sketch and citation trail, not as runnable code.
- **Don't skip the licence check just because something is "in a curated list."** `awesome-quant` and `awesome-systematic-trading` mix MIT/Apache/BSD projects freely with GPL (`backtrader`), AGPL (`OpenBB`, `FinceptTerminal`), LGPL (`nautilus_trader`), and Commons-Clause (`vectorbt`) ones in the same table with no licence column. Every new pick from these lists needs its own licence check before it's treated as more than design-study material — the shortlist below does that per-item.

## What's specifically strong for forex, across all six catalogs

- **`awesome-systematic-trading`'s three currency-factor strategy rows** (`README.md:357-364`) — FX Carry Trade, Currency Momentum Factor, Currency Value/PPP — are the only place in any of these six repos with a documented, cited, Sharpe-scored forex strategy table. Worth reading as literature, not as code (Lean/Quantpedia-locked).
- **`quant-trading`'s "London Breakout backtest.py"** is the single most forex-specific piece of *runnable* code found across all six repos — a session-open-range breakout using the Tokyo-session prior-hour high/low as its threshold, explicitly reasoning about FX session structure in its comments (`London Breakout backtest.py:9-24`). Good as a worked example of session-based level construction; bad as anything closer to production (frictionless, no look-ahead guard visible).
- **`Jiji`** (Ruby/OANDA) is the only *framework*, as opposed to script or client library, in any of these six catalogs that is forex-native from the ground up rather than a multi-asset framework with forex bolted on.
- **`fx-value-date`** and **`sifma-holidays`/`us-equity-market-calendar`** (same author, `moshejs`, TypeScript, zero-dependency) form a small but well-shaped trio for calendar/value-date correctness — directly useful for the financing/rollover line item the synthesis doc calls out as a day-one requirement.
- **`TradeMux`** (commercial, closed-source) is worth naming even though it's not a code dependency: it markets itself as "Unified forex trading API gateway to Metatrader (MT4/MT5), Oanda and cTrader" (`README.md:695`) — i.e., someone is already selling the exact "one broker port abstraction, cTrader included" idea QMF's `qmf.broker` module is built around. That's a signal the abstraction is sound, and a competitive data point, not a dependency.
- **`metatrader5` (PyPI)** and **`mt5-httpapi`** confirm the MT5-needs-Windows constraint the broker-connectivity research already found (`05` in the prior sweep) — both are Windows-terminal-bound, one via a Docker+QEMU/KVM VM wrapper (`mt5-httpapi` description, `awesome-quant README.md:319`) — reinforcing rather than contradicting the earlier "cTrader over MT5" decision.
- **Everything else forex-tagged in `awesome-quant`** (`StockSharp`, `TradeClaw`, `ShowMe`, `capitalcom-cli`, `Prop Firm Risk Calculator`) is either a large multi-asset C# platform with forex as one of many asset classes, or a very new (days-old) single-author tool with no track record — noted for completeness, not recommended for further study.
