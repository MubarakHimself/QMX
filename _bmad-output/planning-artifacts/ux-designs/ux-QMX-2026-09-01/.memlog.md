topic: QMX UX Design
updated: 2026-09-02T09:18

- (intent) User initiated UX planning for QMX: focus on storyboarding, aesthetics, modular component architecture, and ideation without code implementation.
- (insight) Product metaphor: correlation of Agentic ADE/IDE (agent chat, workspace, code/task intelligence) + Bloomberg Terminal (dense financial/execution telemetry, real-time data, multi-dock layout).
- (direction) User directive: Pause visual styling and surface storyboards. Anchor first on the core logic, mental model, and intentionality of the UI. Architectural core: Extensible microkernel/plugin paradigm (ref: Cordis/DeepSeek Harness and get-bb/bb) where UI components and capabilities are dynamically registered, composable, and populated by existing QMX backend subsystems (QMA daemon, QMF risk/data, QMN nodes, QML bots).
- (decision) Three primary UI domains identified: 1. Agentic Workspace (Hermes-style sessions, capabilities, artifacts, scheduled jobs, steerable chat), 2. Quant & Live Execution (Bots, risk books, live telemetry, trading node), 3. Bridge/Interaction Layer (How agents control/inspect bots and how live market events trigger agent sessions).
- (decision) Component architecture confirmed: Wall Street ticker ribbon (open positions, PnL), top mode switcher (SESSIONS / BOTS / TERMINAL), Hermes-style session sidebar (Capabilities, Artifacts, Scheduled Jobs, Pinned/Recent), minimal bottom prompt dock with model picker, kill-switch safety header, drop heavy task graphs/tool cards.
- (decision) Core UI Metaphor: Hyprland-style dynamic tiling workspace compositor. QMX is not a single cramped layout; it is a modular application host where each major subsystem (Overview Dashboard, Hermes Agent Workspace, Fincept Live Quant Terminal, Bot Studio) is an independent full-surface page/workspace plugin. The Global Shell acts as the compositor/window manager with dual navigation (global ribbon/rail + local in-page navigation).
- (decision) Navigation model refined: Thin Left Activity Rail for Global Workspace Switching (VS Code / Hermes style), keeping workspace tops clean for internal session/widget tabs. Each workspace maintains its own sovereign internal sidebar and layout.
- (direction) UX Process: Understand and categorize features by visibility scope (Global Ambient, In-Workspace Sovereign, Event-Triggered/Reactive) before finalizing spatial layouts, user journeys, or aesthetic theming.
