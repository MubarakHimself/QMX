# QMF1 supersession audit — zombie prevention

**Scope:** independent Stage 3 audit of the earlier/supporting QMF1 transcript (`SRC-02`) against the later/primary QMX2 transcript (`SRC-01`) and `_docwork/analysis/cross-source-reconciliation.md`.

**Purpose:** preserve useful QMF1 history without allowing overturned architecture, assistant research proposals, or deferred work to re-enter current QMF V1 documentation. This audit does not ratify anything and does not replace the cross-source reconciliation.

## Status vocabulary used here

- **Superseded** — retain the old ruling and its successor; current docs cite only the successor.
- **Dead** — retain the idea and verbatim-derived reason in the dead list; never present it as a current option without a new operator ruling.
- **Deferred** — valid possible future work with a named owner/session, but excluded from QMF V1.
- **Corroborates** — QMF1 independently supports a later QMX2 ruling and may remain as provenance.
- **Provisional / conflict** — evidence points in a direction, but documentation must preserve a GAP rather than settle it.

## 5. Stage 3 zombie-prevention checklist

Before Stage 3 is considered safe from the QMF1 side, verify that the ledger/dead list does all of the following:

- Marks node-first ordering, the full-framework “minimal core” name/cadence, the runtime kernel, Nautilus adoption/spike, universal card, exclusive agent page, Program/Campaign, and snapshot-quality SQS as **superseded or dead**.
- Marks backtesting, Simulator UI, QML, agentic extension plumbing, prop-firm Books, and full researcher tooling as **deferred**, with no V1 feature accidentally tracing them.
- Records the broad QMF1 ring map as an **assistant proposal without operator-backed extraction**, not as an accepted roster.
- Preserves QMF-first documentation, toolbox-not-application, project-owned domain contracts, human-and-agent readability, source precedence, and versioning/durability as **corroborated principles**.
- Keeps Bot cardinality, exit ownership, acquisition lifecycle, dependency policy, and exact `qmf-core` defaults as **gaps/conflicts** rather than silent decisions.
- Does not cite QMF1 research verdicts, tracker edits, or artifact diffs as operator authority unless a direct ruling or later QMX2 confirmation backs them.

If any of these checks fails, a later spec agent can revive a rejected QMF1 architecture while still appearing to cite the transcript correctly. That is the exact failure this audit is meant to prevent.
