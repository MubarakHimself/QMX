## 1. What QMF is — the one ruling everything else hangs on

QMF (Quant Mind Framework) is the **toolbox used to BUILD the applications**, never an application itself. The trading node, backtest workspaces (agents in sandboxes, on demand), and the QMX app + UI are all **built with** QMF later.

**Trading-node authority model (corrected per `.recovery/trading-node-delta/recovery-lineage-addendum.md`):** GitBook supplies the **Book/BMS baseline** — the governance rewrite (bots propose; Books own money and permission; BMS accounts and constrains; seven doors; Treasury cycles; constitution). It is NOT the complete source for every surviving mechanic: mechanics GitBook names but never defines are recovered from the legacy `QMX-discussion` corpus; wiki/BMAD material counts claim-by-claim only; **current operator rulings override every historical layer**. The node will be re-specified by reconciling these — that reconciliation is future work, not tonight's. Do not put application runtime (event loops, bot→Book→BMS pipelines, broker sessions) inside the framework's foundation. React analogy: the framework provides parts; the app owns the flow.

Design values (operator-ratified): 100% our own code — mental models only from the 37-repo study (`reference/00-idea-ledger.md`), never code — **clarified 2026-08-18: this bans transplantation, not dependencies; wrapping permissive-licence libraries (TA-Lib, Polars, DuckDB, Optuna, statsmodels, arch…) is expected and encouraged.** **Don't-box-in principle (operator ruling 2026-08-18, platform-wide):** QMF is an open toolbox, always usable alongside plain Python and any external library or method (GAs, trees, RL, LLMs, synthetic data — methods change); uniformity comes from shared contracts, never walls; strictness concentrates in the agentic harness and the promotion gate into the live money path (order, not lock-in); research lanes stay free; built to last (rebuild at most ~twice/year; "Bloomberg Terminal from scratch" ambition); Python core (Rust reserved for UI later; speed via Polars/DuckDB); **written for humans AND agents** — the operator reads this code; permissive-licence dependencies only (LGPL acceptable for unmodified, separately-installed deps); versioned releases, never break consumers; no mock data ships; no bots ship.

## 2. Library #1 — `qmf-core`, "the language" (the first and only near-term build; PROPOSED — pending explicit operator ratification, locks discussion 2026-08-18)

Pure definitions. No loop, no broker, no backtest, no downloads.

1. **Exact money** — price/quantity/balance as exact decimals; floats banned in money paths at the type level.
2. **Exact time** — UTC-nanosecond instants; a "which trading day" concept (sessions/rollover); the two-dates stamp on every fact: when it happened, when it became knowable.
3. **The nouns** — Instrument, Bar, Tick, Order, Fill, Position, Account — style-agnostic (scalp → long hold) and **data-richness-agnostic: seed order-flow concepts now** — DOM/depth-of-market, tape (time & sales), level 2/3 data, order-flow and market-structure primitives — because crypto venues expose rich DOM and the nouns must not need a rebuild when crypto arrives. Forex vs crypto line drawn explicitly: forex has sessions (per-pair relevance, a bot may trade several); crypto is 24/7.
4. **Typed refusals** — every "no" carries a machine-readable name; human-readable explanation alongside.
5. **The stamp machine** — canonical serialization + fingerprinting of any definition (used later by confluences/recipes and results).
6. **Versioning discipline** — definitions carry versions from birth; changing one mints a new version, never rewrites.

**DEFERRED to the agentic era (operator ruling 2026-08-18): everything in this paragraph leaves qmf-core V1.** The agentic system may later adopt the DeepSeek/Cordis harness design near-verbatim (UI layout aside); recorded here as input for that future session (from `reference/06-deepseek-harness-study.md`): 7. the **Context** — the container agent-authored extensions plug into; 8. **disposer discipline** — every registration is reversible/undoable (the one load-bearing rule of the DeepSeek/Cordis model); 9. a **runtime-checked typed event bus**. Extensibility architecture (also pending): one mechanism in the QMF libraries, three composition tiers — agent workspaces fully open (safe by ABSENCE of live providers), app tier reviewed, live node composed at boot + fingerprinted + sealed; promotion between tiers is only ever a human edit. Deny-only guards (a later extension can never undo a refusal) and fail-closed approval carry into the money path. Refused imports: hot reload, auto-reload on vanished services, install-time code execution.

## 3. Corrected vocabulary (operator-ratified tonight)

- **Confluence** = the starting recipe from a hypothesis: Level(s) + Trigger(s) + Confirmation(s). Every slot allows **multiple variants** (six triggers may fire together; a whole bot can serve as a confirmation — composition nests). **No exit in the confluence.**
- **Exits, sizing, risk** = Book territory. (Baseline nuance for the future Book session: the GitBook has bots owning exit organs with Books owning forced exits; dynamic SL/TP-as-Book-grammar was a later delta — reconcile there, not here.)
- **Bot** = confluence + the **binding contract** linking it to a Book (binding not yet designed) — and a bot **accumulates**: as it moves through the system, lineage/genealogy is appended. **Bot variants are first-class**: a bot failing on one pair may work on another, or pass after one trigger variable changes; parent/variant links are tracked (fingerprints connected by lineage).
- **Prop firms are Books** — deferred entirely to the agentic era (baseline agrees: GAP-0004).
- **SQS = Spread Quality Sensor** (operator ruling, confirmed by the legacy corpus). Mechanism recovered: observe live bid/ask spread → compare against a versioned, instrument-aware historical baseline → emit a continuous score + hard-block evidence; MIS carries it without trade authority; the Book's door decides refusal; fail closed when unestablishable. Candidate formula `historical_average_spread / current_live_spread` (1.0 = baseline, >1.0 tighter, <1.0 wider) — a strong candidate, NOT ratified (conditioning/thresholds/cadence open). The later six-component "snapshot quality" aggregate was semantic drift: reopened, to be renamed if ever wanted.
- **R** = one normalized unit of a position's original pre-trade risk — the loss at the original stop (price-distance, pip, and cash forms; full stop-out = −1R, breakeven = 0R). Recovered from legacy; `FORM-0006`'s dimensions are broken — never implement it until explicitly repaired.
- **Three "seat" concepts, never collapsed**: roster seat (bot membership/state in a Book; BENCHED lives here), risk seat (the Book's active risk-allocation channel), legacy capital slot (ancestry only — auctions/DPR/slot tables do NOT survive).
- **Sweep → cap → re-seed cycle = the SCALPING book's pattern**, not a universal law; it's the repeatable template other books will vary from, formed later with the agentic system.
- **Simulator** = a product UI (bot × Book × conditions), later. Backtesting = a **library** (never "engine"), staged funnel, own session — see `tracker/tickets/008` inputs; nothing ratified.
