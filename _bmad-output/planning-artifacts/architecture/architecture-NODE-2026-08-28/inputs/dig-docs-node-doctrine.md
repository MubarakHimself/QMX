- **L39** (`:94`): "The exit-preservation invariant: no control action, of any authority, at any scope, may block a risk-reducing act or the recording of evidence; the blocking half of any control is entries only, and no control kind whose effect is a blanket command-pipe block may be minted." (DEC-0150)

## 2. ADRs (node-binding rulings)

### ADR-0007 venue-neutral integration (`docs/decisions/ADR-0007-venue-neutral-integration.md`)
- Ruling AD-26 secret lifecycle: references never values; single connection-manager holder; values injected at the **composition root** from "the deployment environment's protected store"; account-binding identity `(VenueId, AccountId, role, world)`; one-writer-per-credential; compromise drill (`:35`).
- AD-27 commands/uncertainty (`:36`): command stream = `(VenueId, account)`; four command kinds place/cancel/close_position/close_all (fifth minted later); outcomes `accepted-by-venue | rejected-by-venue | denied-locally | UNKNOWN`; `denied-locally` is an outcome never a refusal; UNKNOWN is a state carrying trigger + submission deadline (declared, application-injected, do-not-default); adapter refuses new commands while UNKNOWN outstanding and "never clears its own block"; unblock only via `resolve_unknown`; recording precedes interpretation; order-state is a read-time fold; "No QMF component retries, flattens, or invents terminal state on UNKNOWN."
- AD-28 adapter contract (`:37`): one neutral port, four contracts CT-18..21; sinks `ObservationSink, JournalSink, RecordSink, SecretStore` injected at root; storage failure triggers command-pipe block in the WriterId-holder; capability surface = static capability declaration + per-`(VenueId,account)` venue-observation profile; six-stage live-path latency decomposition as named rungs, no numeric budgets until measured.
- DEC-0139 (`:38`): broker identity is **deployment configuration**, never architecture; IC Markets is stated intent, not commitment.
- **DEC-0142 node boundary** (`:40`): "The order path, protection funnel, startup semantics, and flatten-authority assignment are node/risk-sitting territory; QMF records only the contract surface AD-26 through AD-28 define and references `tracker/trading-node-notes.md` as a pointer, never absorbing it."
- Consequences (`:50-52`): "connectivity authorizes nothing on its own"; GAP-0039..0046 (risk sitting) open there.

### ADR-0008 book/risk boundary (`docs/decisions/ADR-0008-book-and-risk-boundary.md`)
- Authority order constitutional (`:32`): "bot → book → BMS → operator (L36). One BMS instance per account serves many Books; a Book binds exactly one BMS at a time ...; an instance never spans venues; the risk domain is the binding `(BookInstanceId, BmsInstanceId, VenueId, AccountId, world)`, aligned with the `(VenueId, account)` command stream."
- Kill switch (global, sensor-fed, human de-escalates) and kill line (per-Book capital floor, auto-flattening) "are two different things; flatten authority is assigned (operator always; Book policy through pre-declared triggers; the protection authority where the node's severity policy says so; nobody else); the exit-preservation invariant is law (L39); same-tick priority is one BMS-declared rank table per command stream" (`:32`).
- One control-window contract "serves news, daily dead zone, and session handover buffers — entries-only, live and paper alike, widths configurable with no spine value" (`:32`).
- Admission is three technical layers (linters, demo shakedown, one operator signature) "with no probation and no paper-performance gate" (`:32`).

### ADR-0009 book-level paper mode (`docs/decisions/ADR-0009-book-level-paper-mode.md`)
- Decision (`:32`): "Paper is a Book-level mode ..., expressed as a dated change of the Book's execution binding that mints a new binding epoch, never a new Book. Book modes are `LIVE | PAPER`; `BENCHED` is a bot-seat word only ... every trigger kind declares `routes-to-paper | blocks-paper` (market-risk controls block paper too; capital and authority controls route to paper) ... One active paper-routing target per live binding; the per-intent `execution_target` is resolved once at intent mint ... Paper money is frozen evidence: a configurable UI-editable starting balance, never hand-adjusted; a reset mints an operator-signed paper epoch record; paper P&L never becomes Treasury cash and never buys a seat. Return to live is automatic only for clocked mechanical causes; anything touching real money takes an operator signature; paper performance never authorizes a return."
- Consequences (`:36`): paired demo account holds its own paired BMS instance linked by a typed pairing record; "a silent paper outage alarms like a live one."

### ADR-0012 runtime/packaging/quality — tier-1 OS pins (`docs/decisions/ADR-0012-runtime-packaging-quality.md`)

### ADR-0014 performance/observability/concurrency (`docs/decisions/ADR-0014-performance-observability-concurrency.md`)
- AD-13 measure-then-budget (`:37`): no invented performance numbers; benchmark harness per component measuring speed AND peak memory; baselines scoped to declared `(OS, CPU-class)` tuple; regression fails tier-2 merge gate; one stated constraint: `qmf-core` imports in "well under one second."
- AD-14 loud failure (`:39`): correlation id under field name `correlation_id` propagated across every package boundary; every component exposes no-arg `health()`; "Logs are not journals: log text is display, journals and every evidence stream are evidence encoded per DEC-0106. **Emitted signals must be exportable to Prometheus-class monitoring stacks.**"
- AD-15 concurrency (`:41`): immutable values; purity binds core/indicators/structure; stateful class = stores/recorders/adapters, one-writer-per-stream unlimited readers; "QMF never spawns threads or background work; the application owns all concurrency. Async APIs exist only at the venue network edge."
- Consequences (`:45`): "since everything downstream is built with QMF libraries, that work [scheduling, supervision, retry, parallel-run] is real and lands in the node, backtesting, and ops sittings."

### ADR-0015 promotion (`docs/decisions/ADR-0015-registry-records-and-promotion.md`)
- AD-18 promotion skeleton (`:43`): human-only signer; signed immutable record; mandatory plain-words summary declared an identity field ("the signature attests the exact words the human read"); V1 signing = operator's recorded approval attesting the record's `fp1` string with reviewer identity and instant, no crypto; journal `promotion` event carries only the card fingerprint plus `correlation_id`; "The promotion gate itself — workflow, UI, timing — is platform territory outside QMF."
- AD-16/17 (`:39,:41`): per-kind records, `fp1`-derived stable ids (never minted), append-only JSONL lineage edges, multiplicity recursive; Bot identity = content, binding is a separate dated record; re-binding paper↔live never mints a new Bot.

### ADR-0016 data rooms/journal (`docs/decisions/ADR-0016-data-rooms-splits-journal.md`)
- AD-19 rooms (`:41`): seven room-roles (ingest door, immutable raw archive, processed, journal, split-governed research door, backup, registry room), instantiated per world; cross-world read = `policy rejection`; stores Parquet/DuckDB/SQLite/JSONL (`registry:local_store_engine`); only raw-archive+journal are evidence-bearing; every external fact carries event-time/known-at/source/revision.
- AD-20 backup (`:43`): "nightly, encrypted, versioned, and off-machine to an object-storage bucket (`registry:backup_cadence`, `registry:backup_retention_period`), with automated sample-restore tests and a periodic full-restore rehearsal ...; QMF provides the backup, restore, and verify primitives while the schedule and its execution are application and ops owned. Encryption key custody and the cryptographic dependency are named at the node and ops sitting."
- AD-21 journal (`:47`): "N streams, one per producing component, each under its `WriterId` with gapless per-(writer, boot-epoch) sequences ... Seven event types (`registry:journal_event_types`): decision, order, fill, risk transition, promotion, data quality, and control action."
- Doors (`:49`): idempotent intake keyed on `(source, source-native id, revision)`; news-calendar recorder legal archiving posture "remains an open operator item recorded rather than resolved"; tick sources separately identified (Dukascopy history vs broker feed).

## 3. Scenarios (ratified node behaviours)

### SCN-0004 off-machine backup (`docs/scenarios/SCN-0004-off-machine-backup.md`)
Execution status (`:17`): "backup design and migration ratified; numeric RPO/RTO await the node/ops sitting." Topology (`:21`): "the trading-node VPS records and syncs down, the workstation holds the working archive, and the bucket catches nightly copies." Recoverability claimed only through verify primitives; a recovery/migration never mutates the only copy (`:29`). `registry:backup_recovery_point_objective`, `registry:backup_recovery_time_objective`, `registry:restore_verification_cadence` are "measured and set at that [node/ops] sitting" (`:33`).

### SCN-0005 uncertain venue submission → UNKNOWN (`docs/scenarios/SCN-0005-uncertain-venue-submission.md`)
- Command vocabulary is exactly **five** kinds: `place_order, cancel_order, close_position, close_all, amend_protection` (`:21`). Command stream = `(VenueId, account)`, "coarser than an account binding and strictly finer than a connection; a session-epoch id rides every venue observation" (`:21`). Four outcomes; every outcome mints an observation record and a journal event (`:21`).
- On lost transport: mint explicit UNKNOWN observation carrying trigger (`timeout | transport-error | disconnect`), monotonic elapsed, wall receive instant, submission deadline; recorded/journaled before any state evaluation (`:31`).
- While UNKNOWN outstanding: refuse new commands (`transient venue failure`, after-condition = resolution); `suspend-new` instant; "**Protection commands are not exempt from the block — but a protection act the block refuses never evaporates:** it stands as a **standing protection intent** (AD-36) and is re-decided when the block clears, re-deciding being explicitly not retrying"; cancel/close/amend dispatch ahead of place_order on every shared throttle (`:33`).
- Resolution: `resolve_unknown(command identity, resolution ∈ observed-accepted | observed-absent | operator-attested)`; verdict vocabulary `reconciled | drift | unknown | out-of-lookback`; "a standing protection intent re-evaluates only against a `reconciled` verdict, while `drift`, `unknown`, and `out-of-lookback` alarm and hold the intent open without dispatching" (`:33`).
- Flatten (`:35`): "`close_position`/`close_all` executed mechanically and never adapter-initiated"; adapter's `adapter_self` actions limited to `suspend_new, drain, throttle, session state`; flatten authority assigned (operator unconditional; Book policy via pre-declared trigger classes; protection authority where node severity says `close_all`; never the adapter); "Which effect fires at which severity stays node/trading-node authority."
- Worked numbers (`:39`): "No retry count, pool size, or submission-deadline value is a QMF constant"; command retry prohibited; cited cTrader facts: 50 req/s non-historical + 5 req/s historical per connection, 10s heartbeat bound, ~30-day access token + never-expiring refresh, one-week historical tick-span cap.

### SCN-0006 book paper transition (`docs/scenarios/SCN-0006-book-paper-transition.md`)
- Book modes `LIVE | PAPER`; bot seat `active | benched`; Book binding `live | paper | stood-down` — three vocabularies never interchanged; a mode-field write naming a seat/binding word = `invalid input` (`:21`). Current mode is a read-time fold over the append-only CT-24 transition stream (`:23`).
- Flip = dated change of execution binding minting a new binding epoch, never a new Book; transition record carries mode `PAPER`, `transition_instant`, `trigger_kind`, single resolved `paper_target_ref` (`:33`). Per-intent `execution_target` resolved once at intent mint from `(Book mode, seat state, active-control set)`; live/demo are distinct `(VenueId,account)` streams (`:35`). One active paper-routing target per live binding; no resolvable target = `unavailable dependency` (`:37`). Paper money frozen; reset mints operator-signed `paper_epoch_reset` treasury boundary record (`:41`). Return to live not symmetric; clocked mechanical clear mints CT-24 transition and NEVER a CT-30 `resume` (`:45`).

### SCN-0007 human promotion (`docs/scenarios/SCN-0007-human-promotion.md`)
- Risk slot landed: "three-layer admission packet — Layer 1 registration linters ..., Layer 2 a technical demo/paper shakedown, and Layer 3 one operator signature on one assembled page — plus the CT-32 performance evidence, with **no trial period, probation window, or paper-performance gate** and no paper role permitted to gate live money" (`:21`). Causality gate (GAP-0016) and attempt accounting (GAP-0017) stay deferred to the backtesting sitting (`:23,:25,:37`).

### SCN-0008 pair-scoped news (`docs/scenarios/SCN-0008-pair-scoped-news.md`)
- One control-window contract (CT-31); supersedes 2026-08-18 keep-paper-flowing ruling — "a news window blocks live and paper entries alike" (`:19`). Three ratified kinds `news, daily_dead_zone, session_handover_buffer`; window carried as **two instants, never an offset** (`:23`). Instrument scope declared via dated per-instrument currency-exposure records, "reading a currency out of a symbol is prohibited" (`:25`); `registry:news_blackout_before/after` configurable UI-editable no spine value; ±15-min buffer "on record as withdrawn." Blocks new entries only, live+paper; never an exit/protection amendment/protection action/observation (`:33`). Blocked decision journaled on veto path (`:35`). Fail-closed: missing currency-exposure record → treated-as-affected+blocked+`data quality` alarm (`:37`); "there is no live skip button" (`:41`). window_forced_flat is a Book declaration entering arbitration at rank 2; declaring none is the V1 posture (`:33`).

### SCN-0010 risk boundary conflicts (`docs/scenarios/SCN-0010-risk-boundary-conflicts.md`)
- Priority per `(VenueId, account)` stream with exactly one arbitration point per stream; rank table BMS-declared (`:21,:23`). Class ordering highest-first: "(0) operator action; (1) protection actions (kill-switch class); (2) BMS/Book forced flats (kill-line stand-down, `window_forced_flat`, hold-time or boundary force-flat); (3) fast invalidation (risk-reducing bot exit proposals); (4) ordinary bot exits and protection amendments" (`:23`). Exit-preservation invariant spine law (`:25`). Venue-resident stop sits outside ordering; node-close-vs-venue-stop race resolved by **superseded-by-fill** read-back → `rejected-by-venue (superseded-by-terminal-subject)`, never a stream-blocking UNKNOWN (`:33`). Collapse rule: same mechanical command collapses to one emission, losers journal as suppressed (`:35`). Conflict rule: composing effects (`suspend_new + flatten`) both execute; "a higher-ranked action may never reduce the protection a lower-ranked action would have delivered" (`:37`). Suppression is first-class evidence, referenced by CT-30 fingerprint via `enacts` edges (`:39`). One CT-29 exit record carries resolved `closing_authority` and `close_reason = kill_line_flat` (`:43`).

### SCN-0011 qualifying-loss bench (`docs/scenarios/SCN-0011-qualifying-loss-bench.md`)
- Seat state `active | benched`; `ADMITTED` is not a state (absence of a binding) (`:21`). One CT-29 exit record per virtual (Book) position close (`:25`). Bench counter is a read-time fold over the exit-record stream bounded by the binding epoch; recording-precedes-interpretation: a fill's CT-29 record must persist before any later intent on the same `(Book, Bot)` seat, else `stale evidence` refusal (`:27`). Predicate `realized_r <= -q`; breakevens never count; scratches/partial losses don't count by default; a forced flat counts only if it realized a qualifying loss (`:35-40`). Bench fold "one governed producer, published once and consumed by the door — measurement never acts" (`:44`). Benched seat routes-to-paper via seat record while Book stays LIVE; binding not re-minted (`:46`). Next-open reset is a clocked CT-24 transition, NEVER a CT-30 resume, no operator signature (`:48`).

### CT-20 venue event + reconciliation (`docs/contracts/ct-20-venue-event.yaml`)
Recording precedes interpretation (`:16`). ## 8. Glossary — node-relevant terms (`docs/glossary.md`)

- **Trading Node** (`:588` region, tool-results line 219-221): "A later QMX application that owns live-trading runtime and orchestration. The Trading Node is not qmf-core and is outside QMF V1 documentation scope."
- **Command stream**: `(VenueId, account)` pair — unit of UNKNOWN blocking / WriterId / gapless sequence; coarser than a binding, finer than a connection; session-epoch id rides every observation; "Order-path internals below this contract surface are trading-node territory."
- **kill line**: per-Book capital floor, auto-flattens + stands the Book down, "a 3am breach never waits for the operator"; `loss_floor` = same number.
- **kill switch**: global black-swan authority, stops all new trading live+paper, sensor-fed (MIS and SQS are inputs never authorities), escalates automatically, de-escalates only by a human; effect may add drain/close_all per node severity policy.
- **MIS**: "A future trading-node analytical or machine-learning ensemble consumer. MIS is not a QMF V1 library and is not qmf-indicators."
- **Reconciliation verdicts**: `reconciled | drift | unknown | out-of-lookback`; command pipe only; standing protection intent satisfies only on `reconciled`; "the reconciliation verdict `unknown` is a distinct notion from the UNKNOWN submission outcome."
- **resolve_unknown**: `resolve_unknown(command identity, resolution ∈ observed-accepted | observed-absent | operator-attested)` — application-only, recorded as observation; "The adapter never clears its own block."
- **standing intent**: risk-non-increasing act journaled before dispatch; read-time fold restart-proof; re-decided (not retried) on reconnect; never time-expires; drift/unknown/out-of-lookback hold it open; "A protection act refused by an UNKNOWN block never evaporates."
- **Paper mode / paper epoch** (full text): Book-level mode, dated binding change, standing evidence state; `routes-to-paper | blocks-paper`; one active paper target per live binding; paper money frozen; reset mints operator-signed paper epoch.
- **UNKNOWN (outcome state)**: a state never an error; the block clears only through `resolve_unknown`.
- **SecretRef / SecretValue / Secret reference / Session epoch / Compromise drill / Two-phase wiring / Verify-or-refuse / Venue-observation profile / Venue-scoped market-hours calendar identity / venue_liquidation / Six latency rungs / Schedulable duties** — all defined (tool-results lines 162-285).
- **World**: `live | replay | simulated`; "the Account role, not the world label, carries money-reality, so paper and demo runs are `world = live`"; simulated write = `policy rejection` until GAP-0048.
- **treasury boundary event**: `sweep | refund | re_seed | paper_epoch_reset`; "A boundary event never closes a position and never re-bases a frozen R."
- **prediction linter**: static Book-vs-bot compatibility check (four pinned checks), passes registration and blocks live binding, not a performance gate.
- Retired/prohibited names (`:311+`): archetype (→ strategy family), Backtesting engine (→ QMB, "engine" banned), BotSpec (→ Bot definition), Broker Exam (→ Venue module + QMB), DPR (dead).

## 11. Specific answers requested

**(a) One CLI for the whole platform, or only that QML gets no CLI?**
The corpus does NOT rule that `qmb` is the ONE CLI for the *whole platform including the node*. It rules three things: (1) DEC-0159 within QMB scope — the experimentation product's command is `qmb`, it superseded the position paper's "qmx-command" proposal "(QMX names the entire platform and reuse would confuse operator and agents alike)", and "Every agent workspace provisions the SAME qmb CLI as a pinned dependency — one CLI for agents and operator alike" (`_docwork/ledger.yaml:1492`; `docs/components/qmb.md:170`). (2) DEC-0185 Ruling C — QML gets no CLI of its own: "QML ships NO CLI, ever in this shape — QMB's CLI is the single command-line surface ('just put it under QMB... I don't know why we would have two command lines')" (`_docwork/ledger.yaml:1725`; `docs/components/qml.md:84`). (3) The **trading node's** own operator control doors (CLI/API) are NOT ruled anywhere — the node is explicitly outside QMF docs (Trading Node glossary entry; DEC-0142). So: the platform has one experimentation CLI (`qmb`), QML explicitly gets none, and the qmx-name was rejected for a command; but whether the node's control door is `qmb`, an extension of it, or a distinct surface is an OPEN node-sitting item. The operator's "I don't know why we would have two command lines" signals a strong preference against a second CLI, decided in the QML-vs-QMB context only.

**(b) The "three-tier composition / compose, fingerprint, seal" boot ruling.**
NOT FOUND in the corpus. Grep for "compose ... fingerprint ... seal", "fingerprint the composition", "seal the composition", "three-tier composition", "three tier composition" over `docs/`, `_docwork/ledger.yaml`, and `_bmad-output/planning-artifacts/` returned zero hits. No boot-time "compose → fingerprint → seal" three-tier ceremony for the trading node is ratified. This is an OPEN item the node sitting must design (likely by analogy to QMB's resolved-config fingerprint + the composition-root injection pattern + the registry as-of-set freeze).

**(c) The "three calendars" ruling.**
Ratified as DEC-0106 (AD-8). Bare "calendar" is never used. A venue's measured daily-bar boundary, once verified, mints its own venue-scoped market-hours calendar identity, independent of QMF's forex 17:00-NY rule.

**(d) What the observability lens already specifies** — see §6: logs-vs-journals encoding, `correlation_id`, `health()`, seven journal event types, venue journal-kind bindings, Prometheus-class exportability obligation, measure-then-budget with `(OS, CPU-class)` baselines, six latency rungs, and a full state/event-triggered alarm table — with EVERY numeric threshold, severity tier, notification destination, paging route, dashboard, and log-level taxonomy explicitly deferred to the node/ops sitting.
