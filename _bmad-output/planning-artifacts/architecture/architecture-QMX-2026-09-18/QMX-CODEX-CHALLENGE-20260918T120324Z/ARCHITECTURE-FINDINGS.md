# Independent Stage B architecture findings

Candidate: `qmx-workflows-arch-2026-09-18-a`  
Implementation inspected: `270e992995c2378ca63cf6343254ef8140a8c97e`  
Docs revision: `b8b4d21a3d6ec33158254f1827912c8fc0c4dcc3`

## Verdict

The candidate is directionally coherent and materially better than the stale audit, but it is **not architecture-complete in the reviewed scope and is not ratified**. It establishes a useful composition vocabulary, preserves QMF as one framework, keeps specialists, separates Board layout from execution, treats UI adapters as non-authoritative, and protects the existing Book/BMS default. It does not yet close several failure transitions where two conforming implementations could produce duplicate external effects, ambiguous command ownership, unrecoverable workflow state, or misleading provenance.

Severity means: **Critical** blocks acceptance of the stated scope or can violate command/effect safety; **High** permits incompatible implementations or unrecoverable evidence; **Medium** leaves a bounded contract/journey incomplete; **Low** is clarification or evidence debt.

## Candidate improvements observed only in Pass II

These were not credited to the independent baseline because they were visible only after the freeze:

- explicit `ContributionHit` as an additive, non-fp1 discovery rail;
- Board layout separated from Graph Template, Task Graph and ungoverned library calls;
- explicit edge mapping modes and full-DAG intent;
- journal-projected product sessions, immutable authoring/app-use profiles, session-owned context and grants;
- app-use change requests with validation and versioned handoff rather than direct implementation edits;
- four non-compulsory app-composition modes with intersection authority;
- explicit no-dummy Book/BMS rule and preservation of the default path;
- data recipe/provider/stream semantics, provider ≠ venue, and source-disagreement preservation;
- sequential deployment intent, placement preflight and split persistence ownership;
- presentation adapters declared non-authoritative, headless packs allowed, and PM retained as Portfolio Manager;
- mutation testing correctly limited to an optional test-strength probe in WSL/POSIX disposable copies.

## Existing strengths and evidence limits

The pinned implementation supports the QML mill/Stage-0 types and host research store, QMF data/risk ownership, QMB Book/BMS-gated doors, and QMN’s closed venue selector. This challenge executed 47 focused QML tests and the QMN conformance slice (5 passed, 1 skipped). Those results do not prove workflow orchestration, product sessions, ContributionHit, package lifecycle, a complete non-Book path, or QML→QMB→QMN integration. QMA remains source-inspected because the candidate’s own recon records its selected environment as blocked.

## Acceptance disposition

Do not ratify or start Documentation Factory from this package. Grok reconciliation should first resolve AF-01 through AF-13, then close the schema/journey gaps. A safe implementation sequence can still prototype isolated validators and schemas, but only after the affected decisions are reconciled and without treating them as architecture acceptance.
