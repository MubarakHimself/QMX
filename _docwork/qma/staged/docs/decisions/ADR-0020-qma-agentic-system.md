# ADR-0020: The QMX agentic system — QMA SDK, daemon and wire

Date: 2026-08-29. Status: accepted — the QMA architecture spine (`architecture-QMA-2026-08-28/ARCHITECTURE-SPINE.md`, FINAL, AD-1..AD-29) is adopted in full and absorbed as a new application-layer consumer on the operator's absorption order (SRC-15, 2026-08-29). Design is ratified by delegation under the sitting's "I draft, operator ratifies" mode; the multi-round validation pass closed `verified=true dry=true remaining=0` on 2026-08-29. Nothing here authorizes code — implementation ships only through the factory pipeline (DEC-0329).

## Context

The corpus needs an owning record for the QMX agentic system: the daemon plus the QuantMind Agents SDK plus the daemon-to-UI wire contract, an application layer that stands on QMF exactly as QMB and QML do. The system runs many agents at once — a persistent named actor per desk, Agents and Subagents in loops and graphs, work coordinated through a daemon-owned Task Graph rather than chat (DEC-0332). Its first requirement, stated by the operator, is unattended operation: agents that keep working while he is away (DEC-0328).

Two facts forced a clean-room decision rather than a salvage. First, the operator deleted the earlier `workroom/agentic-system-planning` folder to the Recycle Bin and ruled it not an input; nothing may be salvaged from it (DEC-0332; salvage from that folder is dead, DEC-0379). Second, the design transcript that seeded the sitting is brainstorming, not a specification — it carries an overcooked platform shape (trust tiers, a capability solver, a large injectable context fabric, an eight-type memory taxonomy, permanent named specialist rosters, group chat as coordination, an eleven-entry loop registry) that the operator himself flagged as overcooked. The sitting treated the transcript as a seed to build on and to cut back (DEC-0332, DEC-0333).

The QMA design must also honor a live constraint the parent corpus already ratified: the money path is closed to agents. Nothing above a Bot touches the market (constitution L36); risk, sizing and live-trading authority stay with the GitBook and trading-node corpus (DEC-0350). QMA's only output into the money path is a candidate artifact a human promotes — never a binding, a sizing decision or an order (DEC-0341, DEC-0324 in the umbrella, AD-25).

The sitting ran autonomously by operator delegation. The reviewer gate grew the spine from 26 to 29 ADs (AD-27 store lifecycle/backup/restore, AD-28 money-path reachability, AD-29 routines/continuation), and the validation pass applied six surgical divergence fixes before closing dry: the telemetry store carries no `journal_seq` (AD-6); the AD-11 registration validator also rejects `verifier_ref`; `role.base` is written only by an operator-principal `role.set_base` command with a matching AD-24 gate; `unknown_tail` is the second daemon-authored ledger entry (AD-9/AD-8); the definition store has a single agent write exception (AD-8); and `model_family` is optional (AD-15/AD-10) (DEC-0329).

## Options considered

1. **Reopen the deleted `workroom/agentic-system-planning` kernel-contract design** and build the QMX agentic system from that Cordis-kernel research. Rejected: the operator deleted it and ruled it not an input, and salvage from it is Cut — nothing enters unless the transcript independently says the same thing (DEC-0332, DEC-0379).
2. **Host foreign agent runtimes** (the Claude Agent SDK, OpenAI or LangGraph loops) behind a QMX agent protocol and adapters inside QMA workers. Rejected: QMA owns its runtime bottom-up, and this shape is Cut (DEC-0360); the paired foreign-harness model-proxy shim is Cut with it (DEC-0370).
3. **The transcript's overcooked platform machinery.** Each shape was rejected against the single-operator reality and is Cut: extension trust tiers, a marketplace and install counts (DEC-0361); a provides/requires/optional capability dependency solver (DEC-0362); a twenty-service injectable context fabric (DEC-0363); an eight-type memory taxonomy (DEC-0364); the general-IDE lifecycle events (DEC-0365); hot-module reload and reactive re-mount (DEC-0366); isolate/intercept and label-joined config scopes (DEC-0367); multi-tenant memory and knowledge machinery (DEC-0372); cloud service tiers, vendor telemetry, account slots and mobile clients (DEC-0373); a shared account-level cloud computer with per-actor screens (DEC-0369); and permanent named specialist rosters (DEC-0374). Every one is a dead row of the Cut-outright table, which is spine law and revives only by a spine amendment (DEC-0329).
4. **Group chat as the coordination substrate and an eleven-entry loop registry as the organizing centre.** Rejected: parallel workers synchronize through the daemon-owned Task Graph, not chat (DEC-0377, dead), and graphs — not loops — are the organizing centre, with Loop reduced to a node kind inside an authored Graph Template (DEC-0378 dead; DEC-0340).
5. **A Trading-desk execution tool, "paper only" included.** Rejected: QMA's money-path output is never an order, paper is an account role on a real venue rather than a sandbox, and no execution tool exists at any account role — this shape is Cut and its refusal is the ground for the AD-16/AD-28 money-path reachability barrier (DEC-0375 dead; DEC-0341).
6. **A relay/signing public-messaging bus** for the Agent Bus. Rejected: sovereign multi-tenant messaging for strangers is Cut; a single-operator daemon's durable, addressed, non-authoritative bus needs none of it (DEC-0368 dead; DEC-0319).
7. **Fold the agentic system into an existing component** (`qmf-core`, `qmf-registry`, QMB or QML). Rejected on authority grounds, detailed in the architecture-preflight verdict.
8. **Chosen — three new application-layer packages in the contract-hub house style.** `qma-core` (definitions only, depending only on `qmf-core`), `qma-daemon` (the only process that runs anything and the sole writer) and `qma-wire` (the only cross-boundary contract package), adopting the spine AD-1..AD-29 in full so QMF and QMA read as one system (DEC-0329, DEC-0335).

## Decision

The QMX agentic system is realized as three new application-layer packages built on QMF: **`qma-core`, `qma-daemon` and `qma-wire`**, sharing the Python namespace `qma.*` with no blanket `qmx.` prefix anywhere (DEC-0337). The spine AD-1..AD-29 is adopted in full; the Cut-outright table and the Deferred table are spine law, every Deferred row keeps its stated revisit condition, and no Cut row revives except by a spine amendment (DEC-0329).

- **Naming.** QMA expands to QuantMind Agents and names the **SDK only** — never a framework and never the whole system; the system in prose is "the QMX agentic system (QMA)". "Quantum Mind" is a retired dictation error (DEC-0330). The persistent named organizational actor is a **Quant**, never Bot and never Steward, addressed `quant:<desk_slug>/<quant_slug>` over the five fixed desks; Bot stays the platform's trading-strategy instance (DEC-0331, DEC-0306). Retired names are recorded, and the Backtesting Service is the `analysis-backtest` plugin's daemon-half adapter, never a second backtesting engine (DEC-0348).
- **Contract-hub shape.** `qma-core` is definitions-only and mints no parallel base for anything `qmf-core` defines; `qma-daemon` runs everything and is the sole writer of the journal, the SQLite store and the artifact store; `qma-wire` is the only cross-boundary contract. Every runtime concern enters through one of the seven core-defined ports (MemoryProvider, ModelDeployment, ExecutionEnvironment, KnowledgeSource, ToolAdapter, ComputeProvider, ContextCompiler), and plugin contributions are reversible and scoped (DEC-0335).
- **Runtime.** One Python 3.14 asyncio daemon, built with the QMF libraries so no QMF contract is re-implemented across a language boundary; language-specific workers and non-Python clients attach over `qma-wire`, and the RLM kernel is a persistent Python interpreter inside the Analysis worker's Docker container over the typed `host_request` bridge (DEC-0334).
- **Wire.** A single versioned daemon-to-UI contract binds now: the envelope, JSON-RPC 2.0 over WebSocket with HTTP GET for queries, an `initialize` handshake negotiating a semver `protocolVersion` that is additive-only within a major, and durable event replay through `wire.attach` (DEC-0304). The first milestone is a Quant reachable through models over the wire; the UI and its extension SDK are Deferred while the wire contract and the variables registry bind now (DEC-0333, GAP-0081).
- **Enforcement and control.** Hooks are the single enforcement and control surface: every daemon-owned primitive ships its own `before_`/`after_` events, closed-and-addable, and nothing agent-produced becomes runtime state by itself — it passes the AD-22 admission gate (DEC-0339, DEC-0321 in the umbrella). The three control primitives are Graph Template (authored, versioned, stateless), Loop (a node kind with a runtime-owned stopping condition, budget and escalation) and Skill, with the load-bearing Graph Template vs Task Graph name split (DEC-0340).
- **Evidence.** Ledgers are task-level: one Task Ledger per Task for its life, a Quant Ledger only for a desk's lead Quant, an Experiment Ledger per experiment, and Research/Trading/Development/Analysis/PM ledgers are read-time views; the event journal is neither a ledger nor telemetry (DEC-0338). Telemetry is a separate system exported through a swappable OTel port (DEC-0322 in the umbrella).
- **Model and memory.** The model proxy is the deterministic chain ModelClass to Deployment to Credential Broker with OpenCodex behind the Deployment contract, a mandatory loopback bind and no account pooling by QMA (DEC-0344). Memory enters through the MemoryProvider port with admission-gated candidates and the `NoMemoryProvider` refusal when nothing is bound; Knowledge is a read-only, provenance-carrying corpus behind the KnowledgeSource port, its two confidences never conflated (DEC-0342, DEC-0343). The three closed verbs stay distinct: memory candidates are **admitted**, RefinementProposals are **applied**, and only a human **promotes** a registered artifact into the live zone outside QMA (DEC-0345).
- **Money path.** No execution tool exists at any account role, paper included; the act-level deny-list refuses every order, binding, sizing and promotion act at the Tool Registry, and placement and registration refuse any environment or edge that could reach the trading node (DEC-0341, DEC-0327). Dependency direction is default-deny: `qma-daemon` reads-and-calculates `qmf-registry` and `qmf-risk` over an enumerated surface, `qmf-venue` is importable by nothing QMA, and plugin halves meet only at `qma-wire` (DEC-0347, DEC-0301). The deployment envelope is a workstation-default daemon with Docker workers on that host and remote deployment dialing out through AD-17, driven from the UI and never a QMA command line; the trading-node VPS is untouched (DEC-0336, DEC-0324 in the umbrella).
- **Vocabulary reconciliation.** `plugin` for a desk extension package and the qualified "RLM kernel" for the Analysis worker's interpreter are adopted for QMA prose only; the parent ban stays in force for QMF/QMB/node prose, and QMA's adoption is never presented as lifting it (DEC-0346).

The constitution binds QMA read-only at the touchpoints L17, L18, L30 (roster-scope annotation), L31, L33, L34, L35 (adopted), L36, L38 and L39; QMA amends no parent by assertion (DEC-0350).

## Architecture-preflight verdict

**New `COMP-QMA-CORE`, `COMP-QMA-WIRE` and `COMP-QMA-DAEMON`** — with the inventory read and every reuse candidate named and refused by id:

- **`COMP-QMF-CORE`** is a framework-neutral, definitions-only library that must contain no broker, event loop, backtest, download or trading-node runtime (L13, DEC-0022 in the parent ledger). It supplies the nouns, fingerprints (`fp1`), typed-refusal base, ids and `correlation_id`, money and time types that `qma-core` builds on and never re-derives (DEC-0302 in the umbrella), but it cannot host a daemon, a wire contract or an agent runtime — a definitions boundary runs nothing (authority boundary).
- **`COMP-QMF-REGISTRY`** owns record kinds and lineage; it is a records boundary, never an orchestration or agent-runtime surface. `qma-daemon` reaches it read-and-calculate only — importing value types, typed refusals and pure calculation surfaces and writing only content-addressed dev-zone candidate artifacts — and may construct no binding, Book, BMS, seat, control-action, exit, priority-rank or promotion record and call no zone-transition surface (DEC-0347, DEC-0301). A records package cannot own the daemon that schedules missions.
- **`COMP-QMB`** is the experimentation host: it consumes bots and runs backtests, and is never an agent runtime. QMA reaches it through the single `qmb` door — the `analysis-backtest` plugin's daemon half places exactly one `qmb` job per environment and holds no scheduler, no parallelism and no state of its own — so the agentic runtime cannot live inside the backtesting host without inverting the door/library law (DEC-0316 in the umbrella, DEC-0348).
- **`COMP-QML`** is the bot-authoring library (ADR-0018): it authors and gates Bot definitions and confluences. Strategy and Bot semantics stay QML- and `qmf-registry`-owned; QMA holds references and content-addressed candidates only and redefines neither noun (DEC-0313 in the umbrella, GAP-0085). QML cannot host an agent daemon.
- **The trading node** is the money path. No QMA agent, worker, environment, browser session or computer-use session may reach a venue, broker, exchange, trading-node or platform-registry control surface by any means; the AD-28 reachability barrier refuses any such placement or registration, and the trading-node VPS is untouched (DEC-0327, DEC-0341). The node cannot host or be reached by the agentic runtime.

**Dead-list check.** The dead engine/service decisions of the parent corpus stay dead and untouched — the central backtesting service (DEC-0084), Nautilus contract adoption (DEC-0085) and the adoption spike (DEC-0086) are not revived by this ADR. The twenty QMA Cut-outright rows are minted dead in this increment (DEC-0360..DEC-0379), each a rejected shape that revives only by a spine amendment (DEC-0329).

What the three components own that nothing else does: `qma-core` owns the port definitions, the plugin contribution surface, the closed vocabularies and the money-path deny-list enumeration (DEC-0300 in the umbrella, DEC-0335); `qma-wire` owns the envelope, the command/query/event families and the protocol-version ladder (DEC-0304); `qma-daemon` owns the journal, the closed store list, the Task Graph, the hooks registry, the three ledgers, the model proxy, the Tool Registry, the compute router, the admission gate and the scheduler (DEC-0305, DEC-0339, DEC-0338). No existing component's authority shrinks.

## Consequences

- **Makes easier.** A single versioned wire lets a client and the daemon be built apart without the client breaking on every daemon change (DEC-0304). One deterministic total order (`journal_seq`) and one sole writer make replay and audit exact (DEC-0305). Hooks as the single enforcement surface put every guard in one place (DEC-0339), and the admission gate keeps arbitrary agent output out of runtime state (DEC-0321 in the umbrella).
- **Makes harder — deliberately.** No agent can reach the market by any means: an execution act is refused at tool registration and a reaching environment is refused at placement, not softened at runtime (DEC-0341, DEC-0327). No memory or knowledge engine ships in v1 — both enter through a port, and `recall` returns `NoMemoryProvider` until a backend is admitted behind an eval (DEC-0342, GAP-0072). The UI is later and its extension SDK is Deferred (DEC-0333, GAP-0081).
- **Forecloses.** Foreign agent runtimes, trust tiers and a marketplace, a capability solver, group chat as coordination, an eleven-entry loop registry, plaintext credential files as a secret source and git-branch-per-parameter lineage stay dead and do not revive without a spine amendment (DEC-0360, DEC-0361, DEC-0362, DEC-0377, DEC-0378, DEC-0371, DEC-0376). QMA mints no promotion or zone-transition command at all (DEC-0345).
- **Cheap-veto register.** Every Deferred row (GAP-0070..GAP-0091) keeps its stated revisit condition, and every memlog assumption plus the five operator-flagged items — account pooling, the loopback proxy default, the planned Windows VPS, the word `plugin`, and the desk-level lead flag (GAP-0071, DEC-0349) — is overturnable in one line and is surfaced in the changelog. Nothing in these docs grants implementation, credential, order, promotion, live-money or destructive authority (DEC-0329).
- **Authorization.** Design is ratified by delegation; every absorbing document carries `status: ratified`, which is documentation authority only — implementation ships solely through the factory pipeline. Nothing here authorizes code (DEC-0329).
